| 결정 | D18(두 리전 병기, 대표는 시나리오 하나), 서울 리전 막대 색 `#A9C4FD` |

## 세부 계획

**계기:** 사용자가 카드뉴스에 서울 리전 가격이 나오지 않는 이유를 물었다.

| 원인 | 내용 |
|---|---|
| 직접 원인 | 시험 카드가 시뮬레이션 조건(Redshift 미국 리전 컴퓨트 +5%)을 따라 서울 단가가 바뀌지 않았다. 시험 금액도 실제 승인 스냅샷이 아니라 테스트용 고정 가격이었다 |
| 근본 원인 | 차트 장이 대표 조합으로 **리전 하나**만 골랐다. 실제 데이터에서도 서울 리전이 구조적으로 빠지고, T2(서울 프리미엄) 결론이 정기 카드 어디에도 드러나지 않았다 |

**계획 (사용자가 추천안 승인)**

| 단계 | 내용 |
|---|---|
| 1 | 스크립트 차트 장 개정: 리드, 범례, 금액 표기, 두 리전 상시 게재 |
| 2 | `/humanize-korean` 점검 |
| 3 | **실제 승인 스냅샷 금액**으로 시험 굽기. 서울 막대 색 두 안 비교 |
| 4 | 디자인 계획 4-6절, 코드 계획, 결정 로그 반영 |
| 5 | 사용자 승인 |

**검토한 대안:** 리전마다 차트 1장(+1장), 서울 프리미엄 고정 장(+1장). 장수가 늘어 채택하지 않았다.

## 결과

### 차트 장 규격 (디자인 계획 4-6절)

| 요소 | 규격 |
|---|---|
| 범례 | 패널 상단 좌측 `● 미국 리전` `● 서울 리전` |
| 막대 묶음 | 플랫폼마다 막대 2개, 폭 30px, 간격 12px, 상단만 라운드 |
| 막대 높이 | **두 리전 전체 최댓값 기준 비율.** 리전마다 따로 정규화하지 않는다(서울 프리미엄이 높이 차로 보여야 한다) |
| 기준선 | 막대 아래 2px `#EEEDEA` |
| 플랫폼 이름 | 22px/700, 대문자, 흐린 회색 |
| 금액 | 26px/700, 두 줄. 줄마다 범례 색 점을 앞에 붙인다 |
| 색 | 미국 리전 `#2F6BF6`, 서울 리전 `#A9C4FD` |

- **대표 선정 단위를 조합(시나리오·리전)에서 시나리오로 바꿨다.** 리전은 고르지 않고 항상 둘 다 싣는다.
- **약칭 라벨을 쓰지 않는다.** 금액 앞에 `미국`, `서울`을 붙이지 않고 범례 색 점으로 대응시킨다. 규칙 17이 리전 표기를 `미국 리전 · 서울 리전`으로 고정하기 때문이다.
- 리드: `월 사용료 변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.` 무엇의 변동 폭인지 밝힌다.

### 서울 막대 색 비교

| 안 | 색 | 판단 |
|---|---|---|
| **A (채택)** | `#A9C4FD` 연한 파랑 | 같은 색 계열의 명도 차이로 같은 플랫폼의 두 리전임을 보여 준다 |
| B | `#141414` 짙은 색 | 서울 리전이 실제보다 강조돼 보인다 |

### 시험 굽기 [확인]

실제 승인 스냅샷(2026-09-11) + 시뮬레이션 변동. 대표 시나리오는 소규모 BI 대시보드.

| 플랫폼 | 미국 리전 | 서울 리전 |
|---|---|---|
| Snowflake | $1,550 | $2,032 |
| Databricks | $2,056 | $2,708 |
| Redshift | $933 | $1,032 |
| BigQuery | $1,693 | $2,167 |

- 막대 8개와 금액 8개가 1080×1350 안에 넘침 없이 들어간다.
- 서울 막대가 모든 플랫폼에서 더 높아 서울 프리미엄이 그림으로 드러난다.
- 시나리오 이름이 짧은 경우와 긴 경우(비정기 대용량 탐색)를 모두 구웠다. 리드가 두 줄이 되고 넘침은 없다.

## 계획과 달라진 점

- 시험 카드 금액을 테스트용 고정 가격에서 **실제 승인 스냅샷**으로 바꿨다. 이전 시험 카드의 BigQuery 금액이 실제보다 낮았다($1,506 → $1,693).
- 굽기 결함(과제 2-1 결함 수정)을 먼저 고쳐야 확인을 진행할 수 있었다.
