## 세부 계획

**목표:** 디자인 계획 6절 검수 기준 중 **눈으로만 보던 항목을 브라우저 실측으로 바꾼다.** 넘치거나 겹친 카드가 조용히 만들어지지 않게, 어긋나면 굽지 않는다.

### 검사 항목

| 검사 | 근거 | 방식 |
|---|---|---|
| 본문 블록이 상단 바·하단 알약과 겹치지 않는다 | 디자인 계획 6절, 차트 장 여백 30px(2-2) | 브라우저가 계산한 위치로 여백을 잰다. **24px 미만이면 중단**(`MIN_GAP`) |
| 글자가 본문 폭 밖으로 넘치지 않는다 | 6절 | 요소 오른쪽 끝이 본문 폭 안인지 잰다 |
| 줄 수가 상한 안이다 | 스크립트 4절 | 요소마다 실제 줄 수를 센다(`data-lines`: 제목 2, 리드 3, 항목·각주 1 등) |
| 한 음절만 다음 줄로 떨어지지 않는다 | 6절(2-3) | 여러 줄 요소의 마지막 줄 폭이 글자 크기의 **1.6배 미만이면 중단**(`ORPHAN_EM`). 표지 제목의 의도된 줄바꿈은 제외(`data-orphan="skip"`) |
| 화면에 보이는 숫자가 모두 데이터에 있다 | 규칙 16 | 템플릿이 숫자를 새로 만들지 않았는지 보이는 글자로 다시 검사한다. 쪽 표시 `(1/2)`는 뺀다 |
| PNG 1080×1350, PDF 쪽수 = 장수 | 6절 | PNG 헤더와 PDF 바이트에서 직접 읽는다 |

### 측정값 전달 방식 (착수 첫 단계에서 실측으로 결정)

측정 모드 HTML을 브라우저로 열면 스크립트가 장마다 요소 위치와 줄 수를 재어 JSON(ASCII)으로 남긴다. 이 값을 파이썬이 받는 방법이 문제였다.

| 후보 | 방식 | 우려 |
|---|---|---|
| A | `--dump-dom` 표준 출력에서 JSON을 읽는다 | Edge는 분리된 하위 프로세스라 출력을 못 받을 수 있다 [미확인] |
| B | JSON을 `document.title`에 쓰고 `--print-to-pdf`의 PDF 제목에서 읽는다 | 제목 인코딩·길이 [미확인] |

둘 다 실패하면 멈추고 보고하기로 했다.

## 결과

### 측정 방식 실측 [확인]

| 후보 | 결과 |
|---|---|
| **A `--dump-dom` (채택)** | 로컬 Edge에서 5회 모두 출력을 받았다(최대 30KB, 회당 4~10초) |
| B PDF 제목 | 받을 수는 있으나 **4,096자에서 잘린다.** 카드 10장의 측정값을 담지 못한다 |

실측 중 한 번은 A가 값을 찾지 못했다. 시험 페이지의 스크립트가 `<body>`보다 먼저 실행된 탓이었다. 카드 템플릿은 측정 스크립트를 `<body>` 끝에 둔다. 측정 스크립트는 **측정 모드에만** 들어가고, 공개용 `cards.html`에는 없다.

### 굽기 순서

`한글 글꼴 확인(4-1에서 추가) → 숫자 검사 → 레이아웃 측정·검사 → cards.html → 장마다 PNG → cards.pdf → 크기·쪽수 검사`

통과하면 요약을 한 줄 출력한다: `레이아웃 검사 통과: N장, 가장 좁은 여백 Xpx, 가장 오른쪽 글자 끝 Y/Zpx`. CI 기록에서 여유를 확인하는 데 쓴다.

### 실측값 [확인]

| 벌 | 결과 |
|---|---|
| 전형적인 날 5장 | 통과 |
| 변동이 많은 날 10장 | 통과 |
| 여러 줄 요소의 마지막 줄 폭 최솟값 | **5.22em** (한 음절 줄 기준 1.6em과 거리가 멀다) |
| 차트 장 본문-알약 여백 | 131px (조정 전 약 30px) |

이후 실측: CI 5장 가장 좁은 여백 151px·오른쪽 끝 1028/1032px(4-1), 소개 카드 5장 245px·1020/1032px(5-2).

## 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| 측정값 전달 방식 미정 | A `--dump-dom` 채택, `browser.dump_dom` 추가 | B는 4,096자에서 잘린다 |
| 검사 결과는 통과·실패만 | 통과 시 요약(가장 좁은 여백, 가장 오른쪽 글자 끝)을 돌려주고 출력한다 | CI에서 여유를 기록한다(4-1에서 추가) |

## 남긴 것

- **넘침 검사가 막는 것은 줄을 바꿀 수 없는 긴 단어다.** 글자가 길어지면 보통 넘치지 않고 다음 줄로 내려가며, 그때는 줄 수 검사가 막는다.
- 레이아웃 검사는 **두부 글자를 잡지 못한다.** 두부 글자도 폭과 줄 수는 정상으로 잰다(→ 4-1 글꼴 확인).
- 새 장 종류는 측정 대상 요소에 `data-role`·`data-lines`를 붙여야 검사를 받는다(→ 5-1).
