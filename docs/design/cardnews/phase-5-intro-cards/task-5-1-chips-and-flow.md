## 세부 계획

**목표:** 소개 카드 2장(과금 단위가 달라 비교되지 않는다)과 3장(사람의 승인을 거치는 자동화)을 원본 틀의 변형으로 설계한다. 3장을 두는 이유는 이 프로젝트의 특징이 가격 비교 자체가 아니라 **멈추는 지점을 설계한 파이프라인**이기 때문이다(디자인 계획 3-1).

### `chips` 장 제안 (원본 03+04 변형)

- 제목 → 리드 → **흰 타일 2×2**(차트 장 흰 패널과 같은 바탕·모서리) → 각주 1줄
- 타일 안: 플랫폼 이름(굵게) + 과금 단위(보통, 회색)
- 칩 4개: `Snowflake 크레딧` `Databricks DBU-시간` `Redshift RPU-시간` `BigQuery 슬롯-시간`

### `flow` 장 제안 (원본 05 변형)

- 제목 → **세로 4단계** → 각주 2줄. 리드는 없다(확정 문안에 없다)
- 단계마다 번호 원 + 단계 이름, 단계 사이 가는 연결선
- 번호는 **CSS 카운터**로 그린다. 글자가 아니므로 숫자 검사 대상이 아니다
- 멈춤 지점(`검토 요청에서 정지`)은 **번호 원을 채워** 구분한다. 그라데이션은 제목 강조 한 곳만 쓴다(디자인 계획 2절 원칙)

### 공통

- 측정 대상 요소에 `data-role`·`data-lines`를 붙여 레이아웃 검사를 받게 한다(3-3).
- 리드가 없는 장에는 빈 리드 요소를 두지 않는다.
- 각주는 모든 장 종류에서 같은 방식으로 그린다(소개 2·3·4장에 각주가 있다).
- 최종 모양은 실물 확인에서 승인받는다.

### 실물 확인 [확인]

첫 굽기(레이아웃 검사 통과) 뒤 카드 5장을 사용자에게 보였다.

| 확인 사항 | 결과 |
|---|---|
| 2장 제목이 `가격표만으로는 비교되지` / `않습니다`로 끊겨 강조 구절이 두 줄로 갈라진다 | **사용자가 줄바꿈 반영을 승인했다.** `가격표만으로는` / **`비교되지 않습니다`** 로 강조 구절 앞에서 줄을 바꾸고 다시 구웠다 |
| 3장은 리드가 없어 제목과 단계 사이가 다른 장보다 좁다 | 실물 승인. 유지 |

다시 구운 결과도 레이아웃 검사를 통과했다(가장 좁은 여백 245px). 이 줄바꿈은 장 데이터의 `break_before_accent` 표시로 켠다. 다른 장의 제목은 자연 줄바꿈 그대로다.

## 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| 2장 제목은 자연 줄바꿈 | 강조 구절 앞에서 줄바꿈 | 강조 구절이 두 줄로 갈라졌다. 실물 확인에서 사용자가 승인 |
| 각주는 차트 장만 그린다(기존 템플릿) | 모든 장 종류에서 그린다 | 소개 2·3·4장에 각주가 있다. 정기 카드 출력은 같다 |

## 남긴 것
