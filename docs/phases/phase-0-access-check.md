# Phase 0: 막힘 점검

| 항목 | 내용 |
|---|---|
| 상태 | **완료** (2026-09-11) |
| 목표 | 착수 전에 접근권한, 무료 데이터, 약관 때문에 막히는 곳이 있는지 확인하고, 막히는 곳마다 대체 경로를 정한다 |
| 선행 조건 | v2 방향 확정 (`docs/01_plan_v2.md`) |
| 결과 문서 | `docs/02_phase0_report.md` |
| 저장소 변경 | 없음 (읽기 전용 점검) |

## 왜 이 단계가 필요했나
v2 계획은 외부 소스 6종과 게시 채널 2종에 기대고 있었다.
- 외부 소스: AWS, Azure, BigQuery, Snowflake, Databricks, SEC
- 게시 채널: GitHub Pages, LinkedIn

이 중 하나라도 막히면 설계가 바뀐다. 그래서 코드를 쓰기 전에 실제로 호출해 보거나, 공식 문서와 약관 원문을 읽어 확인했다.

## 진행 과정
| 단계 | 점검 대상 | 방법 | 판정 | 핵심 발견 |
|---|---|---|---|---|
| 0-1 | 로컬 환경 | 직접 실행 | 조건부 통과 | gh 토큰에 `workflow` 권한이 없고, duckdb가 설치돼 있지 않다 |
| 0-2 | AWS 가격 파일 | 직접 호출 | 통과 | 리전 파일은 0.1~0.5MB다. 선결제 금액이 시간당 단가처럼 섞여 있다 |
| 0-3 | Azure Retail API | 직접 호출 | 통과 | 서버리스 SQL DBU는 서울이 +35.7% 비싸다. 클래식 DBU는 리전과 관계없이 가격이 같다 |
| 0-4 | 벤더 가격 페이지 | 에이전트 조사 + 약관 원문 직접 확인 | Snowflake·Databricks는 막힘, BigQuery는 통과 | 두 벤더의 약관이 자동 모니터링을 금지한다 |
| 0-5 | LinkedIn API | 에이전트 조사 + 약관 원문 직접 확인 | 막힘 | API 약관 3.1(26)과 사용자 약관 13번이 자동 게시를 금지한다 |
| 0-6 | GitHub | 에이전트 조사 | 통과 | Pages는 공개 저장소에서만 무료다. 새 저장소는 기본값 2개를 바꿔야 한다 |
| 0-7 | BigQuery 샌드박스 | 에이전트 조사 + 원문 직접 확인 | 조건부 | 스토리지 한도가 평생 10GiB이고, 데이터를 지워도 한도가 돌아오지 않는다 |
| 0-8 | 보고서 | 작성 | 완료 | `docs/02_phase0_report.md` |

## 이 Phase가 바꾼 계획
| 바뀐 것 | 이전 | 이후 | 반영 위치 |
|---|---|---|---|
| Snowflake·Databricks 가격 변동 감지 | 페이지 자동 감시 | 분기 1회 알림 + 사용자 확인 | Phase 2-6 |
| LinkedIn 게시 | API로 자동 게시 | A'/A/B/C 중 결정 대기. 자동 게시는 선택지에서 제외 | Phase 3 |
| BigQuery 가격 | 페이지에서 자동 수집 | 수동 가격표. 변동 감지는 가격 문자열 지문 비교 | Phase 1 Task 4, Phase 2-6 |
| Databricks 가격 | 수동 가격표 | Azure 공식 API | Phase 1 Task 3 |
| GitHub 준비 | 저장소 생성만 | 저장소 생성 + `workflow` 권한 + PR 생성 허용 + 토큰 쓰기 권한 | Phase 2-0 |
| H5 실험 | 매일 테이블 재생성 | 작은 사본을 한 번 만들고 60일마다 다시 만든다 | Phase 4-5 |
