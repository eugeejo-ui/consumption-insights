## 방식 결정 (2026-09-12)

**A안을 택한다. 카드와 게시문까지 자동으로 만들고, 업로드와 게시는 사용자가 직접 한다.**

기존에 추천했던 A'안(공식 공유 링크)은 카드뉴스와 맞지 않는다. `linkedin.com/sharing/share-offsite/?url=…`은 **URL 하나를 공유하는 작성 창**을 열 뿐이고, 로컬 이미지 여러 장을 붙이거나 게시문을 미리 채워 넣을 수 없다 [지식]. A'로 올리면 카드뉴스가 아니라 링크 미리보기 게시물이 된다. 아카이브 링크만 공유하고 싶을 때 보조 수단으로 남겨 둔다.

| 안 | 방식 | 판단 |
|---|---|---|
| **A (채택)** | 카드 이미지와 게시문을 자동 생성한다. 사용자가 LinkedIn에서 올리고 게시한다 | 약관 위험이 없고, 카드뉴스 요구사항을 충족한다 |
| A' | 공식 공유 링크로 아카이브 URL을 공유한다 | 이미지 여러 장을 붙일 수 없다. 보조 수단으로만 남긴다 |
| B | 공식 API로 게시한다(사용자가 매번 실행) | 회색지대다. 이미지 업로드까지 자동화하면 약관 3.1(26)에 더 가깝다. 60일마다 토큰을 재발급해야 한다 |
| C | LinkedIn 제외 | 요구사항과 맞지 않는다 |

## 카드뉴스 구성

카드는 **1080×1350(4:5)** 이다. 산출물은 PNG 여러 장과 같은 내용을 묶은 PDF 1개다. 이미지 게시(피드에서 바로 보임)와 문서 캐러셀 게시(넘겨 보기) 중에서 사용자가 그날 골라 쓴다.

| 종류 | 장수 | 구성 |
|---|---|---|
| 소개 (첫 게시물) | 5장 | 무엇을 하는가 → 왜 비교가 안 되는가 → **사람의 승인을 거치는 자동화** → 현재 결과 → 가정과 링크 |
| 정기 (가격 변동) | 4장, **순위가 바뀐 날 5장** | 한 줄 결론 → 단가 변동 → 월 비용 영향 → (순위 변화) → 가정과 링크 |

고정 4장으로 두지 않는 이유가 있다. 순위 변화는 있는 날도 있고 없는 날도 있어서, 고정하면 "순위 변화 없음"만 적힌 빈 장이 나간다.

## 흐름

```
[매일 수집, collect.yml]  단가 변동 감지
   └ E1(월 비용 ±1% 또는 순위 변화) → 글 초안 + 카드 PNG·PDF + 게시문(linkedin.md)
                                    → 검토 PR (본문에 카드 그림과 게시문이 보인다) → [멈춤]
        [사용자가 PR에서 판단 — 셋 중 하나]
         ├ 전면 반려: PR 닫기 → 아무것도 진행되지 않는다
         ├ 문구 반려: revise-copy 라벨 → [revise.yml] 재작성 요청 Issue
         │                              → [Claude] /humanize-korean → 같은 PR 갱신 → 재확인
         │                              (상한 3회. 초과 시 사람이 직접 수정)
         └ 승인: PR 머지
                    │
        publish.yml → 대시보드 게시 + site/cards/<날짜>/ 게시 + 시트 적재
                    │
        [사용자가 폰·PC에서 카드를 받아 LinkedIn에 직접 게시한다]
```

**문구 반려 루프의 한계:** `/humanize-korean`은 Claude 스킬이라 GitHub Actions 안에서 실행되지 않는다. 워크플로가 맡는 범위는 반려 감지와 요청 생성까지이고, 재작성은 Claude가 수행한다. 사용자가 할 일은 라벨을 붙이는 것뿐이다.

## 진행 과정

| 단계 | 작업 | 담당 | 산출물 | 완료 기준 |
|---|---|---|---|---|
| 3-0 | 방식 결정(A안), 디자인 템플릿 수령 | U | `_workspace/card-template/rlvnt-carousel/` | 완료(2026-09-12) |
| 3-1 | **실측**: 설치된 브라우저로 PNG·PDF 굽기, 한글 표시, CI 서버 확인 | C | `publish/browser.py` | 로컬과 CI 양쪽에서 1080×1350 PNG와 PDF가 나오고 한글이 깨지지 않는다 |
| **3-2** | **카드 스크립트 작성 (규칙 16).** 소개 5장과 정기 4~5장의 확정 문안을 먼저 쓴다. `/humanize-korean`으로 점검한다 | C → U | `docs/scripts/cards-script.md`, `docs/scripts/linkedin-post-script.md` | 고정 문안과 자리표시자가 분리돼 있다. 구어체가 없다. **사용자가 문안을 승인한다** |
| 3-3 | 카드 데이터와 게시문 | C | `publish/card_data.py`, `publish/render_linkedin.py` | 순위 변화 유무에 따라 4장·5장이 나온다. 숫자 검사를 통과한다 |
| 3-4 | 카드 HTML 템플릿(디자인 적용)과 굽기 | C | `templates/cards/cards.html.j2`, `publish/render_cards.py` | 외부 요청이 0건이다. **사용자가 카드 실물을 확인한다** |
| 3-5 | 파이프라인 연결 | C | `pipeline.py --cards` | E1인 날 카드와 게시문이 자동으로 생긴다. 굽기가 실패해도 검토 자료는 남는다 |
| 3-6 | 워크플로 연결 | C | `collect.yml` | 검토 PR 본문에 카드가 보인다. 머지하면 `site/cards/`가 게시된다 |
| **3-7** | **문구 반려 재작성 루프 (규칙 16).** `revise-copy` 라벨을 받으면 재작성 요청을 열고, `/humanize-korean`으로 다듬어 같은 PR을 갱신한다 | C | `.github/workflows/revise.yml`, `docs/scripts/revise-loop.md` | 라벨을 붙이면 재작성 요청이 열린다. 재작성 후 같은 PR이 갱신된다. 3회를 넘기면 멈춘다 |
| 3-8 | 소개 카드 구현 | C | `card_data.intro_cards` | 3-2에서 확정한 문안을 그대로 쓴다. 숫자가 최신 승인 스냅샷과 같다 |
| 3-9 | 종단 검증 | C | 검증 기록 | 시뮬레이션 → PR 확인 → 머지 → 게시까지 이어진다 |
| 3-10 | **첫 게시** | U | LinkedIn 게시물 | 사용자가 직접 게시한다. Claude는 게시하지 않는다 |

**3-2를 신설한 이유:** 문안을 확정하지 않은 채 템플릿을 먼저 만들면, 구어체나 어조가 어긋난 문장이 코드에 박힌 뒤에 발견된다. 문안을 먼저 확정하고 승인받은 다음에 자동화한다(규칙 16).

## 사용자가 할 일

1. 이 문서와 코드 계획 2개를 승인한다.
2. **3-2에서 카드 스크립트(문안)를 승인한다.**
3. 3-4에서 카드 실물을 보고 디자인을 확인한다.
4. 문구가 마음에 들지 않으면 검토 PR에 `revise-copy` 라벨을 붙인다. 사유를 PR 코멘트로 남기면 재작성에 반영된다.
5. 3-10에서 LinkedIn에 직접 게시한다.

## 위험

| 위험 | 대비 |
|---|---|
| CI 서버에 한글 글꼴이 없어 글자가 네모로 구워진다 | 3-1에서 실측한다. 없으면 워크플로에서 `fonts-noto-cjk`를 설치한다 |
| 브라우저를 찾지 못해 카드 생성이 실패한다 | 카드 생성 단계를 `continue-on-error`로 두어 검토 PR은 그대로 열린다. 카드는 부가물이다 |
| 브라우저 명령줄 옵션이 버전에 따라 다르다 | 3-1에서 두 가지 표기를 모두 시도하고 결과를 [확인]으로 적는다. 실패하면 멈추고 Playwright 안을 다시 여쭙는다 |
| 한글 제목이 카드 밖으로 넘친다 | 가장 긴 플랫폼 이름·시나리오 이름으로 확인한다. 장 종류마다 최대 글자 수를 정한다 |
| 템플릿 원본 파일이 공개 저장소에 올라간다 | `_workspace/`는 `.gitignore` 대상이다. 커밋 전에 `git status`로 확인한다 |
| 카드에 개인 정보가 남는다 | 좌측 상단은 프로젝트 이름만 넣는다. 실명과 이메일을 넣지 않는다(규칙 11) |
| 재작성 루프가 끝나지 않는다 | 상한 3회를 둔다. 초과하면 자동 재작성을 멈추고 사람이 직접 고친다 |
| 재작성이 숫자를 바꾼다 | 숫자와 자리표시자는 재작성 대상에서 제외한다. 기존 숫자 검사가 그대로 막는다 |

## 제약 (Phase 0에서 확인, 그대로 유효하다)

- LinkedIn **API 약관 3.1(26)**: API로 게시를 자동화하는 것을 금지한다 [확인].
- LinkedIn **사용자 약관 13번**(2025-11-03): 봇이나 무단 자동화로 게시물을 만드는 것을 금지한다 [확인].
- Aside 같은 브라우저 자동화로 로그인 세션을 조종해 게시하는 방식도 위 조항에 해당한다. 계정이 제한될 위험이 있어 **Claude는 구현하지 않는다.**
- 코드에 LinkedIn API 호출을 넣지 않는다. 자동화는 **이미지와 문구 생성까지**다.

## 완료 기준 (게이트)

- 카드와 게시문이 자동으로 만들어지고, 모든 숫자가 `events.json`과 일치한다.
- 검토 PR에서 카드를 미리 볼 수 있다.
- 머지 후 사이트에서 카드를 받을 수 있다.
- 사용자가 첫 게시를 완료한다.
