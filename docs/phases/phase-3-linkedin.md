# Phase 3: LinkedIn 게시

| 항목 | 내용 |
|---|---|
| 상태 | **결정 대기** (방식 선택 필요) |
| 목표 | 아카이브에 게시된 글을 LinkedIn에도 알린다. 단, 약관을 지키는 방식이어야 한다 |
| 선행 조건 | Phase 2 완료(게시할 글과 아카이브 URL이 있어야 한다), 사용자의 방식 결정 |
| 코드 단위 계획 | 방식이 결정되면 `docs/plans/phase3-*.md`로 작성한다 |

## 제약 (Phase 0에서 확인)
- LinkedIn **API 약관 3.1(26)**: API로 게시를 자동화하는 것을 금지한다 [확인].
- LinkedIn **사용자 약관 13번**(2025-11-03): 봇이나 무단 자동화로 게시물을 만드는 것을 금지한다 [확인].
- 사용자가 지시한 aside cli 방식은 로그인 세션을 이용한 브라우저 자동화라서 위 조항에 해당한다. 사용자 계정이 제한될 위험이 있으므로 **Claude는 이 방식을 구현하지 않는다.**

## 선택지 비교
| 안 | 방식 | 필요한 준비 | 반복 부담 | 약관 위험 |
|---|---|---|---|---|
| **A' 공식 공유 링크 (추천)** | PR에 게시문과 LinkedIn 공식 공유 링크(`share-offsite`)를 넣는다 [지식]. 사용자가 링크를 누르고 붙여 넣은 뒤 직접 게시한다 | 없음 | 게시할 때마다 클릭 1~2번 | 없음 |
| A 수동 게시 | 게시문만 만들어 둔다. 사용자가 복사해서 직접 게시한다 | 없음 | 복사·붙여넣기 | 없음 |
| B 공식 API + 매번 직접 실행 | 사용자가 버튼(`workflow_dispatch`)을 누를 때만 Posts API로 게시한다 | LinkedIn 페이지, 개발자 앱, 제품 2개, 토큰 | 60일마다 토큰 재발급, 연 1회 API 버전 점검 | 회색지대 |
| C 제외 | 웹 아카이브만 운영한다 | — | — | 없음 |

## A'안을 고를 경우의 진행 과정
| 단계 | 작업 | 담당 | 완료 기준 |
|---|---|---|---|
| 3-1 | LinkedIn용 게시문 템플릿 작성(요약 3줄 + 아카이브 링크) | C | 게시문에 쓰인 숫자가 `events.json`과 일치한다 |
| 3-2 | 공유 링크 생성 함수(아카이브 URL을 인코딩) | C | 테스트로 링크 형식을 확인한다 |
| 3-3 | 게시 PR 본문에 게시문과 공유 링크를 자동으로 넣는다 | C | 가짜 이벤트로 만든 PR에 두 가지가 들어 있다 |
| 3-4 | 첫 게시 | U | 링크를 누르면 LinkedIn 공유 창에 아카이브 URL이 뜨고, 사용자가 게시한다 |

## B안을 고를 경우
- 사용자가 직접 할 일은 8단계다. 상세 내용은 `docs/02_phase0_report.md`의 0-5에 있다: 페이지 생성 → 앱 생성 → 제품 추가 → 토큰 발급 → Secret 등록 → 60일마다 재발급 → 연 1회 버전 갱신 → 게시마다 실행 버튼.
- [미확인] 앱 인증(Verify)이 필수인지, Share on LinkedIn 권한만으로 `/rest/posts`를 호출할 수 있는지는 확인되지 않았다. B안을 고르면 먼저 실측한다.

## 완료 기준 (게이트)
- 사용자가 방식을 결정한다.
- 결정한 방식을 구현한다.
- 사용자가 첫 게시를 확인한다.
