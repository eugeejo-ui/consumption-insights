| 항목 | 내용 |
|---|---|
| 상태 | 대기 |
| 목표 | ① 실적 공시가 올라오면 H1·H2를 갱신해 글 초안을 만든다. ② BigQuery 실측으로 T3("플랫폼 선택보다 설계 개선이 비용에 더 큰 영향을 준다")를 판정한다 |
| 선행 조건 | Phase 2 완료(이벤트 → PR 흐름), 사용자의 BigQuery 샌드박스 준비 |
| 코드 단위 계획 | 착수할 때 `docs/plans/phase4-*.md`로 작성하고 승인을 받는다 |

## 파트 A: 실적 코너 (벤더 관점, SEC 데이터)
| 단계 | 작업 | 담당 | 완료 기준 |
|---|---|---|---|
| 4-1 | `collectors/sec_filings.py`: companyfacts(매출, RPO), submissions(8-K item 2.02 감지), 본문 파싱(NRR, $1M 초과 고객) | C | 보도자료 파일명이 비표준이어도 인덱스의 EX-99.1 타입으로 찾는다 [확인] |
| 4-2 | E2 이벤트와 실적 글 템플릿(`templates/post_earnings.md.j2`) | C | 8-K 이벤트가 생기면 초안 PR이 만들어진다 |
| 4-3 | 재현 검증 | C | 2026-07 분기 NRR 126%, RPO $9.0B, 커버리지 1.51 → 1.45가 재현된다 [확인] |

**판정 기준** (v1에서 사전에 고정한 값)
- **H1 성장 동력.** 두 가지를 본다.
  - 모든 분기에서 기존 고객이 기여한 비중이 50%를 넘는가
  - 최근 8분기 동안 그 비중의 추세 기울기가 0보다 작은가
- **H2 약정 vs 소비.**
  - (b) 경고: RPO 커버리지가 전년 대비 4분기 연속 떨어지고, RPO 성장률이 매출 성장률보다 낮다
  - (a) 건전: 소진 속도가 오른 뒤 RPO 성장률이 반등한다
  - 둘 다 아니면 판단을 보류한다

## 파트 B: 비용 설계 실험 (고객 관점, BigQuery 실측)
| 단계 | 작업 | 담당 | 완료 기준 |
|---|---|---|---|
| 4-4 | 개인 Gmail로 샌드박스 준비. 서비스 계정 키, JOBS 조회, CTAS·클러스터 테이블이 되는지 실측 | U+C | 세 가지 모두 되거나, 막힌 항목의 대체 경로가 정해진다 |
| 4-5 | H5 실험: V0(전체 스캔, dry run 추정치만) → V1(컬럼 선택) → V2(파티션 필터) → V3(클러스터 사본) → V4(사전 집계) | C | 결과 해시가 모두 같고, 캐시 적중이 false다 |
| 4-6 | 실측값으로 `workloads.yaml`의 플랫폼 간 환산값을 보정한다. Snowflake 30일 트라이얼로 1회 보정하는 것은 선택이다 | C | 보정 전후 값을 결정 로그에 기록한다 |
| 4-7 | (선택) E3 월간 실험 요약 글 | C | 템플릿과 테스트 |

**판정 기준**
- **H5:** V0 대비 V4의 절감률이 90% 이상이면 지지한다.
- **T3:** 설계 개선으로 줄어든 비율이 플랫폼 간 비용 차이(T1)보다 크면 지지한다. 실측은 BigQuery로만 하므로, 일반화할 수 있는 범위를 명시한다.

**스토리지 예산**
- 샌드박스 스토리지는 평생 10GiB이고, 지워도 한도가 돌아오지 않는다 [확인].
- 그래서 사본은 수백 MB로 작게 만들고, 60일 만료 때만 다시 만든다.

## 사용자가 할 일
- 개인 Gmail로 BigQuery 샌드박스 프로젝트를 만든다.
- 서비스 계정 키를 발급해 GitHub Secret에 직접 등록한다.
- 샌드박스로 부족하면 결제 계정 연결 여부를 결정한다(카드 등록이 필요하다).

## 위험과 대응
| 위험 | 대응 |
|---|---|
| 공시의 NRR 문구가 바뀌어 파싱이 실패한다 | 이벤트를 만드는 대신 Issue를 열어 사람이 확인한다 |
| 보도자료 파일명이 비표준이다 | 인덱스의 문서 타입(EX-99.1)으로 찾는다 |
| 샌드박스 제약이 아직 확인되지 않았다 | 4-4에서 실측하고, 막히면 결제 계정 연결이나 로컬 실행으로 대체한다 |
| 캐시 때문에 0바이트로 측정된다 | `use_query_cache=False`로 캐시를 끈다 |
| 쿼리당 최소 10MB가 과금된다 | dry run으로 먼저 확인하고, 과금 상한을 설정한다 |
| 무료 1TiB 한도를 넘는다 | V0는 dry run 추정치만 쓴다 |

## 완료 기준 (게이트)
- 실적 이벤트로 초안 PR이 만들어진다.
- 대시보드에 T3 판정이 표시된다.
- 위 두 가지를 사용자가 확인하면 Phase 5를 계획한다.
