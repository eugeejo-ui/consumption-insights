| 항목 | 내용 |
|---|---|
| 상태 | 대기 |
| 목표 | 승인 흐름이 안정적으로 돌아가면 아카이브 게시를 자동으로 바꾼다. 운영 점검표와 README로 프로젝트를 마무리한다 |
| 선행 조건 | Phase 2·4가 운영 중이고, 초안을 연속 5건 수정 없이 승인했다 |

| 단계 | 작업 | 담당 | 완료 기준 |

## 전환 조건과 되돌리는 조건 (제안)
- **자동으로 바꾸는 조건:** 초안을 연속 5건 수정 없이 승인했다.
- **승인 모드로 되돌리는 조건 (제안):** 아래 중 하나라도 생기면 되돌린다.
  - 숫자 일치 검사가 1번이라도 실패한다.
  - 게시된 글을 수정하거나 삭제하는 일이 생긴다.
  - 사용자가 요청한다.
- **LinkedIn은 자동으로 바꾸지 않는다.** 약관 때문이다(Phase 3).
- 자동 모드에서는 GITHUB_TOKEN으로 머지하면 publish가 트리거되지 않는다. 그래서 같은 실행 안에서 배포한다 [확인].

## 운영 점검표 초안
| 주기 | 할 일 | 담당 |
|---|---|---|
| 매일 | 수집 워크플로가 성공했는지 확인한다(실패하면 Issue가 열린다) | 자동 |
| 분기 | Snowflake·Databricks 가격을 확인하고, 바뀌었으면 수동 가격표를 고친다 | 사용자 |
| 60일 | 저장소 활동과 스케줄이 살아 있는지 확인한다(공개 저장소 60일 규칙) | 자동 + 사용자 |
| 60일 | (B안을 고른 경우) LinkedIn 토큰을 재발급한다 | 사용자 |
| 연 1회 | 의존성과 외부 API 버전을 점검한다 | Claude |

## 완료 기준 (게이트)
- 자동 게시가 안정적으로 돌아간다.
- 운영 점검표와 README를 작성했다.
- 사용자가 최종 확인한다.
