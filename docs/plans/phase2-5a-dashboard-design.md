**컴포넌트 문법**
1. 좌측 사이드바: 로고 → 메뉴(아이콘+라벨, 활성은 옅은 파랑 pill) → 섹션 라벨("Support") → 보조 메뉴
2. 상단 바: 큰 제목 + 우측 아이콘 링크("Download")
3. 필터 줄: 흰 pill 3개(`라벨: 값` + 화살표)
4. KPI 카드: 회색 라벨 → 큰 숫자 → (일부) 파란 스파크라인 + 옅은 면
5. 막대 차트 카드: 좌측 눈금, 옅은 트랙 위에 파란 막대(라운드 캡), 하단 회색 대문자 라벨, 우측 상단 기간 선택
6. 진행바 목록 카드: 썸네일 → 제목 → 그라데이션 진행바 → `숫자% 회색라벨`
7. 리더보드 카드: 아바타 → 이름(굵게) + 보조 줄 → 순위 숫자 + 삼각형

## 2. 우리 데이터로의 매핑

| 템플릿 요소 | 우리 화면 | 비고 |
|---|---|---|
| 사이드바 로고(Tesla) | 프로젝트 워드마크 `consumption-insights` | **타사 상표는 쓰지 않는다.** 색·형태 문법만 따른다 |
| 메뉴(Reports·Library·People·Activities) | 섹션 앵커: 판정 / 월 비용 / 서울 프리미엄 / 가정 공개 | 한 페이지 안 스크롤 이동 |
| Support(Get Started·Settings) | 방법론·저장소 링크 | GitHub 저장소, 수집 방법 설명 |
| 페이지 제목 "Reports" | "데이터 플랫폼 월 비용(TCO) 비교" + 빌드일 | — |
| Download | 스냅샷 CSV 링크(GitHub의 해당 날짜 폴더) | 파일을 새로 만들지 않고 저장소 파일로 연결 |
| 필터 3개 | 리전(미국/서울) · 시나리오(W1/W2/W3) · 보기(합계/컴퓨트·스토리지 분해) | D6에서 상호작용 여부 결정 |
| KPI 카드 6개 | ① 최저 비용 플랫폼 ② 1위와 4위 차이 ③ 서울 프리미엄 범위(최대-최소 %p) ④ T1(미국) ⑤ T1(서울) ⑥ T2 | 판정 카드는 숫자 대신 "기각/지지" + 근거 한 줄 |
| KPI 스파크라인 | 승인 스냅샷이 2개 이상 쌓이면 단가 추이 | 지금은 스냅샷 1개라 자리만 두고 "이력 준비 중" 표시 |
| Activity 막대 차트 | 선택한 시나리오의 플랫폼별 월 비용 막대(트랙 = 최고값, 채움 = 해당 비용) | 템플릿의 "트랙 + 채움" 문법을 그대로 씀 |
| 기간 선택(Month ⌄) | 리전 전환(미국/서울) | 위치와 형태 유지 |
| Weakest Topics(주황) | 서울 프리미엄이 큰 항목 상위 3 | 그라데이션 유지, 값은 `+35.7%` |
| Strongest Topics(초록) | 서울 프리미엄이 낮거나 서울이 싼 항목 3 | 값은 `-3.8%`처럼 표시 |
| 목록 썸네일(사진) | 플랫폼 색 원형 배지(이니셜) | **외부 이미지를 쓰지 않는다**(저작권·오프라인) |
| User/Groups Leaderboard | 시나리오별 순위 카드 2개(예: W1, W3) | 이름=플랫폼, 보조 줄=월 비용·구성 |
| 순위 삼각형 | 이전 승인 스냅샷 대비 순위 변동 | 비교 대상이 없으면 회색 `–` |

**변경하는 부분과 이유**
1. 브랜드 로고 교체: 타사 상표를 쓰지 않는다.
2. 목록 썸네일을 배지로 교체: 외부 이미지 의존을 없앤다.
3. 스파크라인은 이력이 쌓인 뒤 채운다: 지금 넣으면 없는 데이터를 그린 셈이 된다.
4. "People/Activities" 같은 메뉴는 우리 데이터에 없어 섹션 앵커로 대체한다.
