### 1-4. 모든 장에 공통인 틀

```
┌──────────────────────────────────────────────┐
│ CONSUMPTION INSIGHTS          가격 변동 리포트 │  ← 상단 바(밑줄은 좌측만)
│                                              │
│                                              │
│                 본문 영역                     │
│                                              │
│                                              │
│ ╭──────────────────────────────────────────╮ │
│ │ eugeejo-ui.github.io/…        넘기기  / → │ │  ← 하단 알약
│ ╰──────────────────────────────────────────╯ │
└──────────────────────────────────────────────┘
```

- **좌측 상단은 프로젝트 이름만** 넣는다(2026-09-12 사용자 결정). 실명은 넣지 않는다.
- 우측 상단은 회차 라벨이다. 소개 카드는 `소개`, 정기 카드는 `가격 변동 리포트`다.
- 하단 알약 좌측에는 원본의 로고 자리를 대신해 **대시보드 주소**를 넣는다. 카드가 저장돼 퍼져도 출처가 따라간다.
- 우측 "SWIPE / →"는 `넘기기 / →`로 바꾼다(규칙 17). 마지막 장에서는 화살표를 빼고 `끝`으로 둔다.

## 3. 카드 구성

### 3-1. 소개 5장 (첫 게시물)

| 장 | 틀 | 내용 | 숫자 출처 |
|---|---|---|---|
| 1 | `cover` | "데이터 플랫폼 네 곳의 **같은 워크로드** 월 비용을 매일 추적합니다" | 고정 |
| 2 | `chips` (03+04 변형) | "가격표는 있지만 **비교되지 않습니다**" + 단위 칩 4개(크레딧 / DBU-시간 / RPU-시간 / 슬롯-시간) | 고정 |
| 3 | `flow` (05 변형) | "**사람이 컨펌해야** 다음으로 넘어갑니다" + 수집 → 계산 → **검토에서 멈춤** → 게시 | 고정 |
| 4 | `bullets` (06) | "지금까지의 **결과**" + T1·T2 결과, 시나리오별 월 비용이 낮은 순서 | **최신 승인 스냅샷** |
| 5 | `closing` (10) | "숫자보다 **가정**이 먼저입니다" + 대시보드·저장소 주소 | 고정 |

3장을 넣는 이유가 있다. 이 프로젝트의 특징은 가격 비교 자체가 아니라 **사람의 컨펌을 거치도록 설계한 자동화**다. 가격 비교 글은 흔하지만 멈추는 지점을 설계한 파이프라인은 흔하지 않다.

### 3-2. 정기 4~5장 (가격 변동 리포트)

| 장 | 틀 | 내용 | 언제 |
|---|---|---|---|
| 1 | `cover` | 그날의 한 줄 결론 + `작성일 · 단가 N건 변동` | 항상 |
| 2 | `bullets` (08) | 단가 변동 — `Redshift Compute(미국 리전) $0.375 → $0.394 (+5.0%)` | 항상 |
| 3 | `chart` (04) | 월 비용 영향 — 변화가 가장 큰 시나리오·리전의 플랫폼별 막대 4개 | 항상 |
| 4 | `banners` (07) | 순위 변화 — 미국 리전·서울 리전 카드 2장 | **순위가 바뀐 날만** |
| 5 | `closing` (10) | 가정 한 줄 + 대시보드 주소 | 항상 |

평소 4장, 순위가 뒤집힌 날 5장이다. 고정 4장으로 두면 순위가 그대로인 날 "순위 변화 없음"만 적힌 빈 장이 나간다.

**표지 제목 생성 규칙** (자동 생성이므로 규칙을 고정한다)

| 조건 | 제목 |
|---|---|
| 순위 변화 있음 | 월 비용 **순위가 바뀌었습니다** |
| 순위 변화 없음, 월 비용 변화 있음 | 월 비용이 **움직였습니다** |
| 둘 다 없음(단가만 변동) | 단가가 **바뀌었습니다** |

부제는 항상 `{작성일} · 단가 {N}건 변동`이다.

셋째 줄은 평소에는 쓰이지 않는다. 정기 카드는 E1인 날에만 자동으로 만들어지기 때문이다. `--cards <날짜>`로 손수 다시 구울 때를 대비한 기본값이다.

## 4. 넘치는 항목 처리

단가가 한꺼번에 여러 개 바뀌면 한 장에 다 들어가지 않는다. **불릿은 최대 5줄**로 자르고, 남은 건수를 `외 N건`으로 적는다.

여기서 숫자 검사(`check_numbers`)와 충돌한다. `N`은 `events.json`에 없는 계산값이라 검사가 막는다. **검사를 약화시키지 않고**, 카드 데이터를 만들 때 `events` 사전에 `display` 항목을 추가해 그 값을 명시적으로 기록한 뒤 그 사전으로 검사한다. 보강된 사전이 그대로 `events.json`에 저장되므로 나중에 추적할 수 있다.

```json
"display": { "price_change_count": 8, "price_change_omitted": 3 }
```

## 6. 검수 기준

- 1080×1350 PNG가 장수만큼 생기고, 같은 내용의 PDF가 1개 생긴다.
- 모든 장에 상단 바와 하단 알약이 같은 위치에 있다.
- 카드에 쓰인 모든 숫자가 `events.json`에 있다(자동 검사).
- HTML에 외부 요청이 하나도 없다(`<img>`, `<link>`, `@import`, `url()` 없음). 오프라인에서 그대로 구워진다.
- 글자가 네모(두부)로 나오지 않는다. 로컬과 CI 서버 양쪽에서 확인한다.
- 제목이 카드 밖으로 넘치지 않는다. 가장 긴 플랫폼 이름과 가장 긴 시나리오 이름으로 확인한다.
