### 1-4. 모든 장에 공통인 틀

```
┌──────────────────────────────────────────────┐
│ CONSUMPTION INSIGHTS          가격 변동 리포트 │  ← 상단 바(밑줄은 좌측만)
│                                              │
│                                              │
│                 본문 영역                     │
│                                              │
│                                              │
│ ╭──────────────────────────────────────────╮ │
│ │ eugeejo-ui.github.io/…        넘기기  / → │ │  ← 하단 알약
│ ╰──────────────────────────────────────────╯ │
└──────────────────────────────────────────────┘
```

- **좌측 상단은 프로젝트 이름만** 넣는다(2026-09-12 사용자 결정). 실명은 넣지 않는다.
- 우측 상단은 회차 라벨이다. 소개 카드는 `소개`, 정기 카드는 `가격 변동 리포트`다.
- 하단 알약 좌측에는 원본의 로고 자리를 대신해 **대시보드 주소**를 넣는다. 카드가 저장돼 퍼져도 출처가 따라간다.
- 우측 "SWIPE / →"는 `넘기기 / →`로 바꾼다(규칙 17). 마지막 장에서는 화살표를 빼고 `끝`으로 둔다.

## 3. 카드 구성

**문안은 `docs/scripts/cards-script.md`가 정본이다**(규칙 16). 여기서는 장의 종류와 틀만 적는다.

### 3-1. 소개 (첫 게시물) — 5장

| 장 | 틀 | 내용 |
|---|---|---|
| 1 | `cover` (01) | 무엇을 하는가 |
| 2 | `chips` (03+04 변형) | 과금 단위가 서로 달라 비교되지 않는다 |
| 3 | `flow` (05 변형) | 매일 수집 → 월 비용 계산 → 검토 요청에서 정지 → 승인 후 게시 |
| 4 | `bullets` (06) | 현재 결과. 숫자는 최신 승인 스냅샷에서 채운다 |
| 5 | `closing` (10) | 가정과 산출 근거, 링크 |

3장을 넣는 이유가 있다. 이 프로젝트의 특징은 가격 비교 자체가 아니라 **사람의 승인을 거치도록 설계한 자동화**다. 가격 비교 글은 흔하지만 멈추는 지점을 설계한 파이프라인은 흔하지 않다.

### 3-2. 정기 (가격 변동 리포트) — 4장 이상

| 장 | 틀 | 내용 | 장수 |
|---|---|---|---|
| 표지 | `cover` (01) | 그날의 결론 + `작성일 · 단가 N건` | 1 |
| 단가 변동 | `bullets` (08) | 바뀐 단가 전부 | 항목 수에 따라 늘어난다 |
| 월 비용 영향 | `chart` (04) | 대표 조합 차트 + 변동 항목 | 1 |
| 월 비용 변동(이어서) | `bullets` (08) | 대표 장에 못 실은 나머지 | 남은 항목 수에 따라 |
| 순위 변동 | `banners` (07) | 리전별 이전 → 현재 | 순위가 바뀐 만큼 |
| 맺음 | `closing` (10) | 가정과 산출 근거 | 1 |

**장수는 고정하지 않는다.** 변동 항목을 전부 싣는 데 필요한 만큼 늘린다(4절). 최소는 4장이다.

## 4. 항목이 많은 날의 장 분할 (규칙 18)

**생략하지 않는다.** 한 장에 담기지 않으면 같은 종류의 장을 늘려 전부 싣는다. `외 N건` 같은 문구는 쓰지 않는다.

### 4-1. 장수 계산

| 장 | 한 장에 담는 양 | 장수 |
|---|---|---|
| 표지 | — | 1 |
| 단가 변동 | 항목 **5줄** | `ceil(단가 변동 수 / 5)` |
| 월 비용 영향 | 대표 조합 차트 + 변동 항목 **4줄** | 1 |
| 월 비용 변동(이어서) | 항목 **6줄** | `ceil(max(0, 월 비용 변동 수 - 4) / 6)` |
| 순위 변동 | 배너 **2개** | `ceil(순위 변동 수 / 2)`. 없으면 0 |
| 맺음 | — | 1 |

대표 조합은 변동률 절댓값이 가장 큰 (시나리오 · 리전)이다.

### 4-2. 실제 장수 예시

| 상황 | 단가 | 월 비용 | 순위 | 장수 |
|---|---|---|---|---|
| 전형적인 날 | 1 | 3 | 0 | **4장** (표지·단가·영향·맺음) |
| 순위가 바뀐 날 | 1 | 3 | 2 | **5장** |
| 벤더 한 곳이 가격표를 개편 | 8 | 12 | 4 | **9장** (표지 1 · 단가 2 · 영향 1 · 이어서 2 · 순위 2 · 맺음 1) |

### 4-3. 쪽 표시

같은 종류가 2장 이상이면 제목 오른쪽에 `(1/2)`를 붙인다. 1장뿐이면 붙이지 않는다.

### 4-4. 누락 검사 (코드로 강제)

카드에 실린 항목 수를 세어 `events.json`의 항목 수와 대조한다. 하나라도 어긋나면 **생성을 중단한다.** 잘라내거나 요약하지 않는다.

```
len(단가 변동 줄 전체) == len(events["price_changes"])
len(월 비용 변동 줄 전체) == len(events["cost_changes"])
len(순위 배너 전체)     == len(events["rank_changes"])
```

### 4-5. 장수가 많아질 때

장수 상한을 두지 않는다. 다만 **10장을 넘으면** 검토 PR 본문에 경고를 남긴다. 게시 여부와 분량은 사람이 판단한다.

## 6. 검수 기준

- 1080×1350 PNG가 장수만큼 생기고, 같은 내용의 PDF가 1개 생긴다.
- 모든 장에 상단 바와 하단 알약이 같은 위치에 있다.
- 카드에 쓰인 모든 숫자가 `events.json`에 있다(자동 검사).
- **`events.json`의 항목이 하나도 빠지지 않고 카드에 실렸다**(자동 검사, 4-4절). 생략 문구를 쓰지 않는다.
- HTML에 외부 요청이 하나도 없다(`<img>`, `<link>`, `@import`, `url()` 없음). 오프라인에서 그대로 구워진다.
- 글자가 네모(두부)로 나오지 않는다. 로컬과 CI 서버 양쪽에서 확인한다.
- 제목이 카드 밖으로 넘치지 않는다. 가장 긴 플랫폼 이름과 가장 긴 시나리오 이름으로 확인한다.
