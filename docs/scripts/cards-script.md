## 2. 정기 카드 — 가격 변동 리포트

### 1장 · 표지

| 조건 | 제목 (굵은 부분에 강조색) |
|---|---|
| 순위 변동 있음 | 월 사용료 **순위 변동** |
| 순위 변동 없음, 월 사용료 변동 있음 | 월 사용료 **변동** |
| 단가만 변동 | 단가 **변동** |

- 부제: `{작성일} · 단가 {건수}건`
- 리드: `직전 승인 가격({비교일}) 대비 변동 사항입니다.`

### 단가 변동 내역 (항목 5줄마다 한 장)

- 제목: 단가 **변동 내역** `{쪽}`
- 리드: `직전 승인 가격과 달라진 항목입니다.`
- 항목: `{플랫폼} {서비스} · {리전}` / `{전} → {후} ({변화율})`
- **생략 문구를 쓰지 않는다**(규칙 18). 항목이 5개를 넘으면 장을 늘린다.

### 플랫폼별 월 사용료 (차트 1장, 두 리전 병기)

- 제목: 플랫폼별 **월 사용료**
- 리드: `월 사용료 변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.`
- 범례: `미국 리전` `서울 리전`
- 차트: 플랫폼 네 곳마다 미국 리전·서울 리전 막대 두 개를 나란히 세운다.
- 막대 아래 금액: 범례 색 점과 함께 `● {미국 금액}` / `● {서울 금액}`
- 각주(두 문장을 한 줄씩): `금액은 벤더 공시 통화인 미국 달러 기준입니다.` / `약정 할인을 제외한 모델 추정치입니다.`

**서울 리전도 달러로 적는다**(D19). 벤더가 서울 리전 단가를 달러로 공시한다. 원화로 환산하면 서울 프리미엄에 환율이 섞이고, 단가가 그대로여도 환율 변동만으로 E1이 발생한다. 산출 근거 안내는 하단 알약의 대시보드 주소가 대신한다.

**두 리전을 항상 싣는다**(D18). 변동이 한 리전에만 있어도 다른 리전을 빼지 않는다. 대표로 고르는 것은 시나리오 하나이며 리전은 고르지 않는다.

막대 아래에 `미국`, `서울` 같은 약칭 라벨을 쓰지 않는다. 규칙 17은 리전을 `미국 리전 · 서울 리전`으로 표기하도록 고정한다. 약칭 대신 범례 색 점으로 대응시킨다.

### 월 사용료 변동 내역 (항목 6줄마다 한 장)

- 제목: 월 사용료 **변동 내역** `{쪽}`
- 리드: `월 사용료가 ±1% 이상 바뀐 조합입니다.`
- 항목: `{시나리오} · {리전} {플랫폼}` / `{전} → {후} ({변화율})`
- 바뀐 조합을 전부 싣는다.

### 순위 변동 (배너 2개마다 한 장, 순위가 바뀐 날만)

- 제목: 순위 **변동** `{쪽}`
- 리드: `월 사용료가 낮은 순서입니다.`
- 배너: 라벨 `{시나리오} · {리전}` / 이전 `{서열}` / 현재 `{서열}`
- 바뀐 조합을 전부 싣는다.

## 3. 소개 카드 — 첫 게시물 (4장)

### 1장 · 표지

- 제목: 데이터 플랫폼 네 곳의 **월 사용료 추적**
- 부제: `Snowflake · Databricks · BigQuery · Redshift`
- 리드: `같은 워크로드를 기준으로 월 사용료를 환산해 매일 비교합니다.`

### 2장 · 문제 제기

- 제목: 가격표만으로는 **비교되지 않습니다**
- 리드: `네 플랫폼은 과금 단위가 서로 다릅니다.`
- 칩 4개: `Snowflake 크레딧` `Databricks DBU-시간` `Redshift RPU-시간` `BigQuery 슬롯-시간`
- 각주: `단가를 나란히 놓아도 어느 쪽의 월 사용료가 낮은지 판단할 수 없습니다.`

### 3장 · 구조

- 제목: 사람의 **승인**을 거칩니다
- 흐름 4단계: `매일 수집` → `월 사용료 계산` → `검토 요청에서 정지` → `승인 후 게시`
- 각주:
  ```
  가격이 바뀐 날에만 검토 요청이 열립니다.
  승인한 값만 기록과 비교 기준에 사용합니다.
  ```

### 4장 · 현재 결과 (마지막 장)

- 제목: 현재 **결과**
- 항목:
  - `T1 {판정} · 시나리오가 달라도 월 사용료 1위는 동일합니다.`
  - `T2 {판정} · 서울 프리미엄 격차 {격차}%p.`
  - `시나리오별 월 사용료 1위는 {플랫폼}입니다.`
- 각주: `{작성일} 승인 스냅샷 기준입니다. 약정 할인을 제외한 모델 추정치이며 산출 근거는 대시보드에 있습니다.`

### 개정 점검 (2026-09-14, D18 차트 장 두 리전 병기)

실행: run_id `2026-09-14-001`, 경로 light(사전 점수 risk_band low, score 1). 대상은 정기 카드 문안 전체이며 주 대상은 개정한 차트 장이다.

| 항목 | 값 |
|---|---|
| 변경률 | **0.0%** (게이트 스크립트 확정값). 문장 터치율 0.0% (0/24) |
| 등급 | A. 자체검증 6/6 통과 |
| 구조 게이트 | exit 0 수렴. 수치 주입·인용·register 이상 없음 |

고칠 문장이 없었다. 구어체, 권유형 어미, 한 문장에 사실 두 개 이상인 경우가 모두 0건이다. `미국 리전`·`서울 리전`은 약칭 없이 남았고 `월 사용료`는 유지됐다.

**판단이 필요한 사항 (스킬이 수정하지 않고 보고함):** 리드 `변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.`에서 무엇의 변동 폭인지 문장 안에 드러나지 않는다. 지금은 제목 `플랫폼별 월 사용료`가 뜻을 보완한다. 명시하려면 `월 사용료 변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.`로 6자가 늘어난다. 리드 상한(30자 × 3줄) 안에 들어간다. **→ 2026-09-14 사용자가 명시안을 승인했다.** 명시안은 run `2026-09-14-002`에서 후보 구획으로 점검을 통과했다.

### 개정 점검 (2026-09-14, D19 통화 기준 각주)

실행: run_id `2026-09-14-002`, 경로 light(사전 점수 risk_band low, score 0). 대상은 차트 장 개정 각주와 리드 후보 문안이다.

| 항목 | 값 |
|---|---|
| 변경률 | **0.0%** (게이트 스크립트 확정값). 문장 터치율 0.0% (0/9) |
| 등급 | B. S1·S2 잔존 0건, 자체검증 6/6. 변경률이 A 구간(10~25%)에 들지 않아 B로 산정됐으며 문안의 결함 때문이 아니다 |
| 구조 게이트 | exit 0 수렴 |

고칠 문장이 없었다. `벤더 공시 통화`, `미국 달러`, `미국 리전`·`서울 리전`, `월 사용료`가 원형대로 남았다. 각주는 26자·21자 두 문장으로 상한(40자 × 2줄) 안에 든다. 리드 후보(`월 사용료 변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.`)도 어조 문제가 없다.

**스킬이 적용하지 않고 보고한 제안:** 리드를 `{대표 시나리오}의 변동 폭이 가장 큽니다.`로 바꾸면 결론이 문장 앞에 온다. 보수 강도라 적용하지 않았다.

**조판 결함과 처리:** 시험 굽기에서 각주 둘째 문장의 마지막 음절 `다.`만 다음 줄로 떨어졌다. 문안은 바꾸지 않고, 두 문장을 한 줄씩 나누고 모든 카드에 `word-break: keep-all`(단어 단위 줄바꿈)을 적용해 해소했다 [확인].
