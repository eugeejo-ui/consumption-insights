**단가는 반올림하지 않는다.** 반올림하면 작은 인상이 가려진다. 예를 들어 `$0.0208 → $0.0209`가 소수 셋째 자리에서는 `$0.021 → $0.021`로 보인다.

## 2. 정기 카드 — 가격 변동 리포트

### 1장 · 표지

| 조건 | 제목 (굵은 부분에 강조색) |
|---|---|
| 순위 변동 있음 | 월 사용료 **순위 변동** |
| 순위 변동 없음, 월 사용료 변동 있음 | 월 사용료 **변동** |
| 단가만 변동 | 단가 **변동** |

- 부제: `{작성일} · 단가 {건수}건`
- 리드: `직전 승인 가격({비교일}) 대비 변동 사항입니다.`

### 단가 변동 내역 (항목 5줄마다 한 장)

- 제목: 단가 **변동 내역** `{쪽}`
- 리드: `직전 승인 가격과 달라진 항목입니다.`
- 항목: `{플랫폼} {서비스} · {리전}` / `{전} → {후} ({변화율})`
- 단가가 새로 생기거나 없어진 항목: `{플랫폼} {서비스} · {리전}` / `없음 → {후}` 또는 `{전} → 없음` (변화율 없음)
- **생략 문구를 쓰지 않는다**(규칙 18). 항목이 5개를 넘으면 장을 늘린다.

### 플랫폼별 월 사용료 (차트 1장, 두 리전 병기)

- 제목: 플랫폼별 **월 사용료**
- 리드: `월 사용료 변동 폭이 가장 큰 시나리오는 {대표 시나리오}입니다.`
- 범례: `미국 리전` `서울 리전`
- 차트: 플랫폼 네 곳마다 미국 리전·서울 리전 막대 두 개를 나란히 세운다.
- 막대 아래 금액: 범례 색 점과 함께 `● {미국 금액}` / `● {서울 금액}`
- 각주(두 문장을 한 줄씩): `금액은 벤더 공시 통화인 미국 달러 기준입니다.` / `약정 할인을 제외한 모델 추정치입니다.`

**서울 리전도 달러로 적는다**(D19). 벤더가 서울 리전 단가를 달러로 공시한다. 원화로 환산하면 서울 프리미엄에 환율이 섞이고, 단가가 그대로여도 환율 변동만으로 E1이 발생한다. 산출 근거 안내는 하단 알약의 대시보드 주소가 대신한다.

**두 리전을 항상 싣는다**(D18). 변동이 한 리전에만 있어도 다른 리전을 빼지 않는다. 대표로 고르는 것은 시나리오 하나이며 리전은 고르지 않는다.

막대 아래에 `미국`, `서울` 같은 약칭 라벨을 쓰지 않는다. 규칙 17은 리전을 `미국 리전 · 서울 리전`으로 표기하도록 고정한다. 약칭 대신 범례 색 점으로 대응시킨다.

### 월 사용료 변동 내역 (항목 6줄마다 한 장)

- 제목: 월 사용료 **변동 내역** `{쪽}`
- 리드: `월 사용료가 ±{기준}% 이상 바뀐 조합입니다.`
- 월 사용료가 기준 이상 바뀐 조합이 없는 날(순위만 변동)에는 이 장을 만들지 않는다.
- 항목: `{시나리오} · {리전} {플랫폼}` / `{전} → {후} ({변화율})`
- 바뀐 조합을 전부 싣는다.

### 순위 변동 (배너 2개마다 한 장, 순위가 바뀐 날만)

- 제목: 순위 **변동** `{쪽}`
- 리드: `월 사용료가 낮은 순서입니다.`
- 배너: 라벨 `{시나리오} · {리전}` / 이전 `{서열}` / 현재 `{서열}`
- 바뀐 조합을 전부 싣는다.

## 3. 소개 카드 — 첫 게시물 (8장. 단가 항목 수에 따라 장수가 달라진다)

### 1장 · 표지

- 제목: 데이터 플랫폼 네 곳의 **월 사용료 추적**
- 부제: `Snowflake · Databricks · BigQuery · Redshift`
- 리드: `같은 워크로드를 기준으로 월 사용료를 환산해 비교합니다.`

### 2장 · 문제 제기

- 제목: 가격표만으로는 **비교되지 않습니다**
- 줄바꿈: 강조 구절 앞에서 줄을 바꾼다. 자연 줄바꿈으로는 강조 구절이 두 줄로 갈라진다(2026-09-15 카드 실물 확인, 사용자 승인)
- 리드: `네 플랫폼은 과금 단위가 서로 다릅니다.`
- 칩 4개: `Snowflake 크레딧` `Databricks DBU-시간` `Redshift RPU-시간` `BigQuery 슬롯-시간`
- 각주: `단가를 나란히 놓아도 어느 쪽의 월 사용료가 낮은지 판단할 수 없습니다.`

### 3장 · 구조

- 제목: 사람의 **승인**을 거칩니다
- 흐름 4단계: `매일 수집` → `월 사용료 계산` → `검토 요청에서 정지` → `승인 후 게시`
- 각주:
  ```
  가격이 바뀐 날에만 검토 요청이 열립니다.
  승인한 값만 기록과 비교 기준에 사용합니다.
  ```

### 4장 · 현재 순위

- 제목: 월 사용료 **현재 순위**
- 리드: `월 사용료가 낮은 순서입니다.`
- 항목 4개(월 사용료가 낮은 순서): `{순위}위 {플랫폼}` / `미국 리전 {미국 금액} · 서울 리전 {서울 금액}`
- 각주(세 줄, 한 줄에 하나씩): `{작성일} 승인 스냅샷 기준` / `금액은 벤더 공시 통화인 달러 기준` / `약정 할인을 제외한 모델 추정치`
- 비교 기준(각주 아래 한 줄): `비교 기준: 소형 컴퓨트 월 {사용 시간}시간 · 스토리지 {저장량}TB(압축 후)`

**가설과 시나리오를 카드에 싣지 않는다**(2026-09-15 사용자 반려, 2026-09-16 개정 확정). 옛 확정본은 `T1 {판정} · {리전}`, `T2 {판정}`처럼 가설 기호를 실었다. 사전 정보가 없는 LinkedIn 독자에게는 가설이 무엇인지, 무엇을 왜 기각했는지 전달되지 않는다. 1차 개정 초안(`세 시나리오와 두 리전 모두 순위가 같습니다.`)도 같은 이유로 반려됐다. 이 장은 플랫폼별 순위와 두 리전 금액만 싣는다.

**각주는 명사구로 끝맺는다**(2026-09-16 사용자 직접 수정). `…기준입니다.` → `…기준`, `…추정치입니다.` → `…추정치`. 각주는 읽는 문장이 아니라 조건 표시다(규칙 17의 "UI 라벨은 짧은 명사구"). 정기 차트 장 각주는 문장형을 유지한다.

**비교 기준 줄은 작게 둔다**(2026-09-16 사용자 지시). 순위가 어떤 조건에서 나왔는지 확인시키는 용도다. 각주(26px)보다 작은 22px, 흐린 회색, 한 줄이다. 값은 `data/manual/workloads.yaml`에서 온다. `{사용 시간}`은 첫 시나리오의 `hours_per_month`(220), `{저장량}`은 `storage_gb`를 TB로 바꾼 값(10)이다. 저장량은 압축(물리) 후 기준이다(2026-09-11 가정 검토).

- 자리표시자
  - 금액은 **대시보드를 열면 처음 보이는 워크로드**(`workloads.yaml`의 첫 시나리오)의 월 사용료다. 카드에는 워크로드 이름을 싣지 않는다.
  - `{순위}`는 그 워크로드의 미국 리전 기준 순서다. 서울 리전 순서가 다르면 한 항목에 두 리전을 묶을 수 없으므로 **생성을 멈춘다.**
  - `{미국 금액}` `{서울 금액}`은 0-2절의 월 사용료 표기(`$1,032`)다.
  - `{작성일}`은 최신 승인일이다.
- `소형 컴퓨트`는 플랫폼별 Small 1단위(`capacity_per_small`: Snowflake Small, Databricks SQL Small, Redshift 8 RPU, BigQuery 100 slots)를 가리킨다.

### 5장~ · 서울 리전 단가 차이 (항목 5줄마다 한 장)

- 제목: 서울 리전 **단가 차이** `{쪽}`
- 리드: `같은 상품의 서울 리전 단가가 미국 리전보다 높습니다.`
- 리드 둘째 문장(서울 리전 단가가 더 낮은 항목이 있는 날만 붙인다): `항목에 따라 서울 리전 단가가 더 낮은 경우도 있습니다.`
- 항목: `{플랫폼} {서비스}` / `{미국 단가} → {서울 단가} ({차이})`
- 각주: `{작성일} 승인 스냅샷 기준` / `단가는 벤더 공시 통화인 달러 기준`

이 장은 **벤더가 공시한 상품 단가**를 비교한다. 정렬은 차이가 큰 순이다. 항목을 생략하지 않는다(규칙 18). 승인 스냅샷의 단가 항목이 9개이므로 5개 + 4개 두 장이 되고, 제목에 쪽 표시를 붙인다.

`{서비스}`는 0-1절 라벨(컴퓨트·스토리지·주문형 쿼리)이다. `{미국 단가}` `{서울 단가}`는 0-2절 단가 표기이며 반올림하지 않는다. `{차이}`는 `(서울 − 미국) ÷ 미국`을 부호와 소수 첫째 자리로 적는다.

**`프리미엄`을 쓰지 않는다**(2026-09-16, `/humanize-korean` 보고). 일상 한국어에서 `고급·상위 등급`으로 먼저 읽히고, 음수가 되는 항목이 있어 뜻이 어긋난다. D24에서 마무리 안내 장의 `서울 프리미엄`을 바꾼 것과 같은 판단이다.

### 단가 차이 다음 장 · 서울 리전 월 사용료

- 제목: 서울 리전 **월 사용료**
- 리드: `같은 워크로드를 서울 리전에서 돌릴 때의 월 사용료입니다.`
- 항목 4개: `{플랫폼}` / `{미국 금액} → {서울 금액} ({증가율})`
- 각주: `{작성일} 승인 스냅샷 기준` / `금액은 벤더 공시 통화인 달러 기준`
- 비교 기준(각주 아래 한 줄): 4장과 같은 줄을 쓴다

이 장은 단가가 아니라 **같은 워크로드를 돌렸을 때의 월 사용료**를 비교한다. 금액은 4장과 같은 워크로드에서 온다. 정렬은 증가율이 낮은 순이다. `{증가율}`은 `(서울 − 미국) ÷ 미국`이다.

리드는 사실 서술로 둔다. `서울 리전이 더 높습니다`처럼 단정하면 네 플랫폼이 모두 그런 날에만 참이다(2026-09-16, `/humanize-korean` 보고).
