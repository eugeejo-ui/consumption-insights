## 2. 정기 카드 — 가격 변동 리포트

### 1장 · 표지

| 조건 | 제목 (굵은 부분에 강조색) |
|---|---|
| 순위 변동 있음 | 월 비용 **순위 변동** |
| 순위 변동 없음, 월 비용 변동 있음 | 월 비용 **변동** |
| 단가만 변동 | 단가 **변동** |

- 부제: `{작성일} · 단가 {건수}건`
- 리드: `직전 승인 가격({비교일}) 대비 변동 사항입니다.`

### 단가 변동 내역 (항목 5줄마다 한 장)

- 제목: 단가 **변동 내역** `{쪽}`
- 리드: `직전 승인 가격과 달라진 항목입니다.`
- 항목: `{플랫폼} {서비스} · {리전}` / `{전} → {후} ({변화율})`
- **생략 문구를 쓰지 않는다**(규칙 18). 항목이 5개를 넘으면 장을 늘린다.

### 월 비용 영향 (대표 조합 1장)

- 제목: 월 비용 **영향** `{쪽}`
- 리드: `변동 폭이 가장 큰 조합은 {시나리오} · {리전}입니다.`
- 차트: 플랫폼 네 곳의 월 비용
- 항목(4줄까지): `{시나리오} · {리전} {플랫폼}` / `{전} → {후} ({변화율})`
- 각주: `약정 할인을 제외한 모델 추정치입니다.`

### 월 비용 변동 (이어서, 항목 6줄마다 한 장)

- 제목: 월 비용 **변동** `{쪽}`
- 리드: `월 비용이 ±1% 이상 바뀐 조합입니다.`
- 항목: `{시나리오} · {리전} {플랫폼}` / `{전} → {후} ({변화율})`
- 대표 장에 실은 항목을 뺀 나머지를 전부 싣는다.

### 순위 변동 (배너 2개마다 한 장, 순위가 바뀐 날만)

- 제목: 순위 **변동** `{쪽}`
- 리드: `월 비용이 낮은 순서입니다.`
- 배너: 라벨 `{시나리오} · {리전}` / 이전 `{서열}` / 현재 `{서열}`
- 바뀐 조합을 전부 싣는다.

### 맺음 · 가정과 산출 근거

- 제목: 가정과 **산출 근거**
- 본문:
  ```
  과금 단위가 서로 다른 네 플랫폼을 같은 워크로드 기준으로 환산했습니다.
  약정 할인은 제외했고 스토리지는 압축 후 10TB로 통일했습니다.
  산출 과정과 원본 가격을 대시보드에 공개합니다.
  ```
- 하단: 대시보드 주소

## 3. 소개 카드 — 첫 게시물

### 1장 · 표지

- 제목: 데이터 플랫폼 네 곳의 **월 비용 추적**
- 부제: `Snowflake · Databricks · BigQuery · Redshift`
- 리드: `같은 워크로드를 기준으로 월 비용을 환산해 매일 비교합니다.`

### 2장 · 문제 제기

- 제목: 가격표만으로는 **비교되지 않습니다**
- 리드: `네 플랫폼은 과금 단위가 서로 다릅니다.`
- 칩 4개: `Snowflake 크레딧` `Databricks DBU-시간` `Redshift RPU-시간` `BigQuery 슬롯-시간`
- 각주: `단가를 나란히 놓아도 어느 쪽의 월 비용이 낮은지 판단할 수 없습니다.`

### 3장 · 구조

- 제목: 사람의 **승인**을 거칩니다
- 흐름 4단계: `매일 수집` → `월 비용 계산` → `검토 요청에서 정지` → `승인 후 게시`
- 각주:
  ```
  가격이 바뀐 날에만 검토 요청이 열립니다.
  승인한 값만 기록과 비교 기준에 사용합니다.
  ```

### 4장 · 현재 결과

- 제목: 현재 **결과**
- 항목:
  - `T1 {판정} · 시나리오가 달라도 월 비용 1위는 동일합니다.`
  - `T2 {판정} · 서울 프리미엄 격차 {격차}%p.`
  - `시나리오별 월 비용 1위는 {플랫폼}입니다.`
- 각주: `{작성일} 승인 스냅샷 기준입니다.`

### 5장 · 가정과 산출 근거

- 제목: 가정과 **산출 근거**
- 본문:
  ```
  약정 할인을 제외한 모델 추정치입니다.
  가정과 계산 과정, 원본 가격을 모두 공개합니다.
  ```
- 링크: 대시보드 주소 / 저장소 주소

## 4. 글자 수 상한

Task 1 실측에서 104px 제목 10자가 본문 폭(968px)의 약 93%를 차지했다 [확인]. 이를 기준으로 상한을 정한다.

| 역할 | 크기 | 한 줄 상한 | 줄 수 상한 |
|---|---|---|---|
| 표지 제목 | 104px | 10자 | 2줄 |
| 본문 제목 | 76px | 14자 | 2줄 |
| 리드 | 34px | 30자 | 3줄 |
| 항목 | 32px | 32자 | 2줄 |
| 각주 | 26px | 40자 | 2줄 |

상한을 넘으면 카드 생성 시점에 오류로 중단한다. 잘라내지 않는다. 문안이 길어지면 스크립트를 고친다.

## 4-1. 항목 생략 금지 (규칙 18)

**항목을 줄이거나 생략하지 않는다.** 한 장에 담기지 않으면 같은 종류의 장을 늘린다. 장수 계산과 누락 검사는 `docs/plans/phase3-card-design.md` 4절에 있다.

| 장 | 한 장에 담는 항목 수 |
|---|---|
| 단가 변동 내역 | 5 |
| 월 비용 영향(대표) | 4 |
| 월 비용 변동(이어서) | 6 |
| 순위 변동 | 배너 2 |

같은 종류가 2장 이상이면 제목 오른쪽에 `(1/2)`를 붙인다.

## 5. `/humanize-korean` 점검 기록

실행: 2026-09-12, run_id `2026-09-12-002`, 경로 light(사전 점수 risk_band low, score 1).

| 항목 | 값 |
|---|---|
| 변경률 | 1.1% (게이트 스크립트 확정값). 문장 터치율 11.8% (8/68) |
| 등급 | A. 자체검증 6/6 통과 |
| 구조 게이트 | exit 0 수렴. 수치 주입·인용·register 이상 없음 |

**고친 곳**

| 분류 | 전 | 후 |
|---|---|---|
| 연결어미 뒤 쉼표 | 제외했고**,** / 추정치이며**,** | 쉼표 제거 |
| 피동 술어 | 대시보드에 공개돼 있습니다 | 대시보드에 공개합니다 |
| 조사 중복 | 워크로드를 기준으로 월 비용으로 | 워크로드 기준으로 월 비용을 |
| 중복 수식 | 순서도 함께 바뀌었습니다 | 순서도 바뀌었습니다 |
| 용어 | 현재 판정 결과 | 현재 결과 |
| 용어 | 사람의 컨펌을 거칩니다 | 사람의 승인을 거칩니다 |
| 용어 | 어느 쪽이 저렴한지 | 어느 쪽의 월 비용이 낮은지 |

**유지한 곳**
- 문장형 제목 2건(`가격표만으로는 비교되지 않습니다`, `사람의 승인을 거칩니다`). 명사구로 줄이면 의미가 약해진다.
- `약정 할인을 제외한 모델 추정치입니다` 반복. 카드마다 독립된 고지 문구다.

**용어 결정:** 공개 문안에서는 **승인**을 쓴다. `컨펌`은 외래어 구어체다. 내부 문서와 규칙 14의 `컨펌`은 그대로 둔다. 문서 용어와 공개 문안 용어를 구분한다.
