> **소개 게시문 개정 확정** (2026-09-16 사용자 승인). 첫 게시물이므로 맨 앞에 문제의식과 측정 결과를 세 줄로 밝힌다(`데이터 플랫폼 네 곳의 월 비용을 추적합니다.`를 대신한다). `두 배`는 카드에 실은 워크로드의 실측이다(미국 리전 2.28배, 서울 리전 2.62배) [확인]. 다른 워크로드는 1.5배여서 종결을 과거형으로 둔다. 정기 게시문(1절)은 그대로 둔다. 첫 줄의 `매일`을 뺐다. 카드뉴스를 매일 올린다는 뜻으로 읽힌다. 수집 주기는 본문의 `가격이 바뀐 날` 문장이 알린다.
> **어조:** executive 보고체. 결론을 앞에 두고 근거를 뒤에 둔다. 구어체를 쓰지 않는다.
> **한도:** LinkedIn 본문 3,000자. 실제 문안은 900자 이내로 유지한다.
> **보완안 확정** (2026-09-15 사용자 승인, Task 3 Step 0). 정기 게시문의 `영향` 표현을 `변동 폭`으로 바꾸고, 월 비용 변동이 있는 날만 그 줄을 출력하도록 조건을 붙였다. 그 결과 순위 줄이 단독으로 나오는 날이 생겨 `순서도`를 `순서가`로 바꿨다. `월 비용` 용어는 D17에 따라 다른 대화에서 교체하므로 그대로 둔다.

자리표시자와 금액 표기는 `docs/scripts/cards-script.md` 0절·0-2절과 같다. 단가는 반올림하지 않고, 없는 쪽은 `없음`으로 적는다.

## 1. 정기 게시문 — 가격 변동 리포트

```
데이터 플랫폼 월 비용 변동 · {작성일}

직전 승인 가격({비교일}) 대비 단가 {건수}건이 바뀌었습니다.

[바뀐 단가를 한 줄도 빠짐없이 반복한다]
▪ {플랫폼} {서비스} · {리전} {전} → {후} ({변화율})

[월 비용 변동이 있는 경우] 월 비용 변동 폭이 가장 큰 조합은 {시나리오} · {리전}입니다.
[순위가 바뀐 경우] 월 비용이 낮은 순서가 바뀌었습니다.

과금 단위가 서로 다른 네 플랫폼을 같은 워크로드 기준으로 환산해 비교했습니다.
약정 할인을 제외한 모델 추정치이며 가정과 계산 과정을 모두 공개합니다.

{대시보드 주소}

#데이터플랫폼 #클라우드비용 #FinOps #Snowflake #Databricks #BigQuery #Redshift
```

## 2. 소개 게시문 — 첫 게시물

```
같은 워크로드를 돌려도 플랫폼마다 월 비용이 두 배 넘게 벌어졌습니다.
데이터 플랫폼은 사용량이 늘수록 이 격차도 커집니다.
네 곳을 같은 기준으로 환산해 비교하고 계산 과정을 공개합니다.

Snowflake, Databricks, BigQuery, Redshift는 과금 단위가 서로 다릅니다.
크레딧, DBU-시간, RPU-시간, 슬롯-시간을 나란히 놓아도 비교가 되지 않습니다.
같은 워크로드 기준으로 월 비용을 환산해 비교했습니다.

파이프라인은 가격이 바뀐 날 중간 결과를 만든 뒤 정지합니다.
검토 요청을 승인해야 게시와 기록이 진행됩니다.
승인하지 않은 값은 비교 기준으로도 쓰지 않습니다.

약정 할인을 제외한 모델 추정치입니다. 가정과 계산 과정, 원본 가격을 모두 공개합니다.

{대시보드 주소}

#데이터플랫폼 #클라우드비용 #FinOps #데이터엔지니어링
```

## 3. 검사 규칙

- 본문에 등장하는 모든 숫자는 `events.json`에 있어야 한다. 없으면 생성을 중단한다.
- **바뀐 단가를 하나도 빠뜨리지 않는다**(규칙 18). `외 N건` 같은 생략 문구를 쓰지 않는다.
- 대괄호 조건부 줄은 해당 조건일 때만 출력한다.
- `월 비용 변동 폭이 가장 큰 조합`은 `cost_changes` 중 변화율 절댓값이 가장 큰 항목이다. 동률이면 목록의 첫 항목이다.
- 해시태그는 고정이다. 자동으로 늘리거나 줄이지 않는다.
- 본문이 **3,000자를 넘으면 생성을 중단하고 사람에게 알린다.** 항목을 잘라서 한도를 맞추지 않는다.
- **가정과 산출 근거 고지는 게시문에 유지한다.** 카드에는 해당 장을 두지 않으므로(D16) 게시문이 유일한 서술 위치다.
