# LinkedIn 게시문 확정 문안 (스크립트)

> **상태: 초안.** 규칙 16에 따라 코드보다 먼저 작성한다. `/humanize-korean` 점검과 사용자 승인을 거친 뒤 Task 3으로 넘어간다.
> **어조:** executive 보고체. 결론을 앞에 두고 근거를 뒤에 둔다. 구어체를 쓰지 않는다.
> **한도:** LinkedIn 본문 3,000자. 실제 문안은 900자 이내로 유지한다.

자리표시자는 `docs/scripts/cards-script.md` 0절과 같다.

## 1. 정기 게시문 — 가격 변동 리포트

```
데이터 플랫폼 월 비용 변동 · {작성일}

직전 승인 가격({비교일}) 대비 단가 {건수}건이 바뀌었습니다.

[바뀐 단가를 한 줄도 빠짐없이 반복한다]
▪ {플랫폼} {서비스} · {리전} {전} → {후} ({변화율})

월 비용 영향이 가장 큰 조합은 {시나리오} · {리전}입니다.
[순위가 바뀐 경우] 월 비용이 낮은 순서도 바뀌었습니다.

과금 단위가 서로 다른 네 플랫폼을 같은 워크로드 기준으로 환산해 비교했습니다.
약정 할인을 제외한 모델 추정치이며 가정과 계산 과정을 모두 공개합니다.

{대시보드 주소}

#데이터플랫폼 #클라우드비용 #FinOps #Snowflake #Databricks #BigQuery #Redshift
```

## 2. 소개 게시문 — 첫 게시물

```
데이터 플랫폼 네 곳의 월 비용을 매일 추적합니다.

Snowflake, Databricks, BigQuery, Redshift는 과금 단위가 서로 다릅니다.
크레딧, DBU-시간, RPU-시간, 슬롯-시간을 나란히 놓아도 비교가 되지 않습니다.
같은 워크로드 기준으로 월 비용을 환산해 비교했습니다.

파이프라인은 가격이 바뀐 날 중간 결과를 만든 뒤 정지합니다.
검토 요청을 승인해야 게시와 기록이 진행됩니다.
승인하지 않은 값은 비교 기준으로도 쓰지 않습니다.

약정 할인을 제외한 모델 추정치입니다. 가정과 계산 과정, 원본 가격을 모두 공개합니다.

{대시보드 주소}

#데이터플랫폼 #클라우드비용 #FinOps #데이터엔지니어링
```

## 3. 검사 규칙

- 본문에 등장하는 모든 숫자는 `events.json`에 있어야 한다. 없으면 생성을 중단한다.
- **바뀐 단가를 하나도 빠뜨리지 않는다**(규칙 18). `외 N건` 같은 생략 문구를 쓰지 않는다.
- 대괄호 조건부 줄은 해당 조건일 때만 출력한다.
- 해시태그는 고정이다. 자동으로 늘리거나 줄이지 않는다.
- 본문이 **3,000자를 넘으면 생성을 중단하고 사람에게 알린다.** 항목을 잘라서 한도를 맞추지 않는다.

## 4. `/humanize-korean` 점검 기록

카드 문안과 함께 점검했다. 결과는 `docs/scripts/cards-script.md` 5절에 있다. 게시문에서 고친 곳은 연결어미 뒤 쉼표 1건, 중복 수식 1건, 조사 중복 1건이다.
