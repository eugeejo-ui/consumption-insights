## 게시 전 결함 수정: PDF 강조 문구 테두리선 (2026-09-15)

### 발견

사용자가 `cards.pdf`를 열었더니 그라데이션 강조 문구(`월 사용료 추적`, `승인`, `대시보드`, `비교되지 않습니다`)마다 **문구를 감싸는 상자 가장자리에 희미한 주황 실선**이 보였다. PNG에는 없다. PDF 안에서 스크롤하면 사라졌다 다시 나타난다.

### 원인 [확인]

- 강조 문구는 `background: linear-gradient(...)` + `background-clip: text` + `color: transparent`로 그린다(그라데이션 사각형을 글자 모양으로 오려 낸다).
- **PNG**는 브라우저가 픽셀로 바로 그리므로 문제가 없다.
- **PDF**로 저장하면 Chromium이 이 기법을 문구마다 "그라데이션 사각형 + 소프트 마스크 두 겹"으로 기록한다. PDF 내부 확인 결과:
  - 사각형이 강조 상자 전체를 채운다(예: 표지 `48 573 615 138 re f`).
  - 첫 번째 마스크는 상자 사각형을 반전한 것(`/TR {1 exch sub}`)이다.
  - 두 번째 마스크는 글자 모양이다.
  - 소개 카드 PDF에 `/SMask`가 11개 있다.
- 보기 프로그램이 첫 마스크의 가장자리를 부드럽게(안티에일리어싱) 그리면서 반전 값이 0이 되지 않는다. 그 결과 사각형 테두리가 한 픽셀 폭으로 비친다.
- 배율과 화면 조각에 따라 가장자리가 걸리는 픽셀이 달라서 나타났다 사라진다.

### 재현 [확인]

사용자의 보기 프로그램과 다른 렌더러(pdf.js 3.11.174, 헤드리스 Edge)로 표지 강조 상자 오른쪽 가장자리 열을 쟀다. 상자 높이 전체에서 배경 대비 색 편차의 평균을 비교했다.

| 배율 | 현재 PDF | 승인된 PNG 5장으로 조립한 시험 PDF |
|---|---|---|
| 1.37배 | 2.0 | 0.0 |
| 2.13배 | 1.7 | 0.0 |
| 3배 | 13.2 | 0.0 |

3배 확대 이미지에서 현재 PDF는 강조 문구를 감싸는 선이 보이고, 시험 PDF는 선이 없다. 시험 PDF는 5쪽, 273,919바이트, `/SMask` 0개, 이미지 5개다. 쪽 전체가 여백 없이 카드로 채워진다.

LinkedIn은 올린 PDF를 자체 변환기로 그려서 보여 준다. 그 변환기에서 선이 보이는지는 확인할 방법이 없다 [미확인]. 서로 다른 렌더러 두 곳에서 재현됐으므로 게시 전에 고친다.

### 결정 D23 (2026-09-15 사용자 승인, A안)

**카드 PDF는 굽기가 끝난 PNG를 한 쪽에 한 장씩 실어 만든다.** 카드 HTML을 PDF로 직접 인쇄하지 않는다.

| 안 | 내용 | 채택 |
|---|---|---|
| **A** | 승인 대상 PNG로 PDF 조립 | **채택.** PDF와 PNG의 모습이 같아지고, 원인(소프트 마스크)이 사라진다. CI에서 굽는 정기 카드도 같은 함수를 쓰므로 함께 해결된다 |
| B | 강조 문구를 단색으로 | 기각. 승인한 디자인이 바뀐다 |
| C | 강조 문구를 SVG 글자로 | 기각. 템플릿과 레이아웃 검사를 크게 고쳐야 한다 |

**대가**
- PDF 안의 글자를 선택하거나 검색할 수 없다. LinkedIn 문서 게시와는 관계없다.
- 크게 확대하면 선명도가 PNG 해상도(1080×1350)에서 멈춘다.

## 로컬 Edge 결함: `--dump-dom` 출력이 비어 있다 (2026-09-16)

| 항목 | 내용 |
|---|---|
| 증상 | 로컬에서 카드를 구우려 하면 `DOM을 받지 못했다. --headless=new: 종료 코드 0, 출력 0자`로 멈춘다. 레이아웃 검사가 이 출력을 쓰므로 굽기 전체가 막힌다 |
| 실측 [확인] | Edge는 종료 코드 0에 출력 0바이트다. 파일 리디렉션(`>`)으로 받아도 0바이트다. 같은 조건에서 **Chrome은 정상**(54바이트)이다. 화면 캡처와 PDF 굽기는 Edge에서도 정상이다(파일로 쓰기 때문) |
| 정황 | Edge 로그에 `edge_process_pooling` 메시지가 있다. 풀링된 다른 프로세스가 일을 넘겨받으면서 표준 출력이 사라지는 것으로 보인다 [가정]. 사용자 Edge 창이 떠 있는 상태에서 재현됐다 |
| 영향 범위 | **로컬 굽기만 해당된다.** CI는 Chrome을 쓰므로 영향이 없다(3-6 실측). 게시된 카드와 게시문에도 영향이 없다 |
| 임시 대응 | 이번 검증은 Chrome을 먼저 쓰도록 바꿔 돌렸다. 전체 134개 통과 |
| 고칠 안 | `publish/browser.py`의 `dump_dom`이 브라우저 후보를 차례로 시도하고, 출력이 비어 있으면 다음 후보로 넘어가게 한다. 화면 캡처·PDF 경로는 그대로 둔다. 테스트는 첫 후보가 빈 출력을 줄 때 다음 후보로 넘어가는지 확인한다 |

### 수정 결과 (2026-09-16) [확인]

- 테스트를 먼저 썼다. 첫 브라우저가 빈 출력을 주면 다음 브라우저로 넘어가는지, 모두 실패하면 시도한 브라우저를 모두 알리는지 확인한다. 수정 전 코드에서 둘 다 실패했다.
- `publish/browser.py`
  - `browsers()`를 더했다. 설치된 브라우저를 우선순위대로 돌려준다. `BROWSER_BIN`이 가장 우선한다.
  - `dump_dom()`이 브라우저 × 헤드리스 표기 조합을 차례로 시도한다. 실패 사유에 브라우저 이름을 함께 남긴다.
  - 화면 캡처와 PDF 경로는 그대로 두었다. 파일로 쓰기 때문에 Edge에서도 정상이다.
- 전체 테스트 134 → 136개 통과. **로컬에서 실제 굽기 테스트가 다시 돈다**(Edge가 빈 출력을 주면 Chrome으로 넘어간다) [확인].

## 게시 전 수정 5: 게시문 도입 문단에 리전 격차 추가 (2026-09-16)

### 요청

리전 비교 두 장을 더했으니 게시문 방향도 바꾸자는 요청이다. 사용자가 두 줄을 제시했다. 플랫폼 간 격차가 두 배를 넘는다는 줄과, 같은 플랫폼이라도 사용 지역에 따라 30% 넘게 벌어진다는 줄이다.

### 초안과 사용자 수정

1차 초안에서 두 곳을 지시와 다르게 냈고, 이유를 함께 보고했다.

| 항목 | 지시 | 초안 | 이유 |
|---|---|---|---|
| 리전 격차 | `30%가 넘게` | `최대 31.7%` | 실측이 +14.7% ~ +31.7%로 갈린다. `30% 넘게`는 Redshift(+14.7%)가 반례가 된다 |
| 종결 | 현재형 | 과거형 | 두 숫자 모두 워크로드 한 종류의 실측이다 |

사용자가 최댓값 표기는 받아들이고, 종결은 현재형으로 직접 고쳤다. 네 줄을 다음과 같이 확정했다.

```
같은 워크로드를 돌려도 플랫폼마다 월 비용이 두 배 넘게 차이가 납니다.
같은 플랫폼이라도 서울 리전은 미국 리전보다 월 비용이 최대 {리전 최대 차이} 높습니다.
결국 데이터 플랫폼은 사용량이 늘수록 두 격차가 커지는 구조입니다.
네 곳을 같은 기준으로 환산해 비교하고 계산 과정을 공개하겠습니다.
```

현재형은 측정 범위보다 넓게 읽힌다는 점을 보고했고, 사용자가 그대로 진행하기로 했다. 다른 워크로드는 플랫폼 간 격차가 1.5배다 [확인].

### 결정: 숫자를 자동으로 채운다

### 게시

### 발견: 문서 뷰어가 카드를 뭉갠다 [확인]

게시된 게시물에서 소개 4장(`월 사용료 현재 순위`)의 제목 강조 부분이 색 띠로 깨져 나왔다. 제목 글자와 순위 네 줄, 금액은 읽히는 상태다.

파일을 다시 확인한 결과 카드 PDF에는 결함이 없다.

| 항목 | 값 |
|---|---|
| 쪽마다 실린 것 | 1080×1350 이미지 한 장(8쪽 모두) |
| 압축 | FlateDecode(무손실). `/DCTDecode`(JPEG) 0건 |
| `/Shading`(그라데이션 도형) | 0개 |
| `/SMask`(투명 마스크) | 0개 |

D23으로 PDF를 PNG 사진첩으로 바꿔 놓았기 때문에 파일 안에는 글자도 그라데이션도 없다. 따라서 LinkedIn이 PDF를 자기 뷰어로 다시 그리는 단계에서 생긴 것으로 본다 [가정]. LinkedIn에는 접근하지 않으므로 더 좁힐 수 없다(규칙 9).

### 결정 D26 (2026-09-16 사용자 결정)

- **다음 게시부터 PNG 8장을 사진으로 올린다.** 뷰어를 거치지 않아 원본 그대로 나온다.
- **카드 PDF는 계속 만든다.** 사이트에 두고 내려받아 보는 용도다. 굽기와 검사(쪽 수·이미지 수·마스크 없음)는 그대로 유지한다.
- **이번 게시물은 그대로 둔다.** LinkedIn은 게시 후 첨부 파일을 바꿀 수 없어 고치려면 지우고 다시 올려야 한다 [지식]. 정보 전달은 되고 있다.
- 대가: 피드에서 표지 한 장이 크게 뜨지 않고 타일로 깔린다. 독자가 한 번 눌러야 넘겨 본다 [지식].
