## 목표

Task 3이 만든 장별 데이터를 **1080×1350 PNG 여러 장과 PDF 1개**로 굽는다. 디자인은 사용자 템플릿(`_workspace/card-template/rlvnt-carousel/`)과 디자인 계획을 따른다.

이 Task는 **렌더링 품질을 코드로 검사**하는 것이 핵심이다. 디자인 계획 6절 검수 기준 중 눈으로만 보던 항목을 브라우저 실측으로 바꾼다.

| 검사 | 근거 | 방식 |
|---|---|---|
| 본문 블록이 상단 바·하단 알약과 겹치지 않는다 | 디자인 계획 6절, Task 2 인계(각주-알약 여백 30px) | 브라우저가 계산한 위치로 여백을 잰다. 24px 미만이면 중단 |
| 글자가 카드 밖으로 넘치지 않는다 | 디자인 계획 6절 | 요소의 오른쪽 끝이 본문 폭 안에 있는지 잰다 |
| 줄 수가 상한 안이다 | 스크립트 4절 | 요소마다 실제 줄 수를 센다(제목 2, 리드 3, 항목·각주 1 등) |
| 한 음절만 다음 줄로 떨어지지 않는다 | 디자인 계획 6절 | 여러 줄 요소의 마지막 줄 폭이 글자 크기의 1.6배 미만이면 중단 |
| 화면에 보이는 숫자가 모두 `events.json`에 있다 | 규칙 16 | 템플릿이 숫자를 새로 만들지 않았는지 보이는 글자로 다시 검사한다 |
| PNG가 1080×1350이고 PDF 쪽수가 장수와 같다 | 디자인 계획 6절 | PNG 헤더와 PDF 바이트에서 직접 읽는다 |

## 원본 대조 결과와 디자인 조정안 (결정 필요)

템플릿 원본 PNG를 다시 실측했다. 디자인 계획 1-2절 토큰은 "구현하며 원본과 대조해 맞춘다"는 근사값이다. 대조 결과 아래 여섯 곳을 조정하려 한다. **승인하면 디자인 계획을 먼저 고친 뒤 구현한다**(규칙 10).

| # | 항목 | 디자인 계획 | 조정안 | 근거 |
|---|---|---|---|---|
| 1 | 좌우 여백 | 56px | **48px** | 원본의 상단 바와 하단 알약이 x=48에서 시작한다 [확인] |
| 2 | 하단 알약 | 높이 96px, 테두리 `#F3C9BC` 단색 | **높이 56px, 아래 여백 48px, 테두리 2px 그라데이션**(왼쪽 연한 살구색 → 오른쪽 산호색) | 원본 알약은 y=1245~1301이고 테두리 색이 좌우로 변한다 [확인]. 본문 공간이 40px 늘어 각주-알약 겹침 위험이 줄어든다 |
| 3 | 본문 수직 위치 | top 250px 고정 | **상단 바와 알약 사이 세로 가운데 정렬** | 원본 03·07·08·10은 본문 블록의 중심이 y=660 안팎으로 카드 중앙 근처다 [확인]. 내용이 적은 장의 아래 여백이 큰 문제(Task 1 인계)도 해소한다 |

**실물 확인 때 함께 고를 것 1건:** 원본 제목은 보통 굵기이고 강조 단어만 약간 굵다. 조정안 4(전체 700)와 **원본에 가까운 안(일반 부분 400, 강조 부분 700)**을 표지 한 장씩 구워 함께 보여 드린다. 선택 전까지 기본값은 700이다.

## 장 종류별 레이아웃

모든 장은 같은 틀(상단 바, 가운데 정렬 본문 블록, 하단 알약) 안에 본문만 다르다.

| 장 | 원본 틀 | 본문 구성 |
|---|---|---|
| `cover` | 01 | 제목 104px(일반 부분 한 줄, 강조 부분 다음 줄) → 부제 → 리드 |
| `bullets` | 08 | 제목 76px + 쪽 표시 → 리드 → 항목 목록(`▪` 기호, 굵은 첫 줄 + 회색 둘째 줄) |
| `chart` | 04 | 제목 → 리드 → 흰 패널(범례, 막대 8개, 플랫폼 이름, 금액 두 줄) → 각주 두 줄. 규격은 디자인 계획 4-6절 |
| `banners` | 07 | 제목 + 쪽 표시 → 리드 → 짙은 배너 1~2개. 배너 안: 라벨 → `이전` + 서열 → `현재` + 서열. 서열은 34px, 최대 2줄, ` › ` 앞뒤에서만 줄을 바꾼다 |
| `closing` | 10 | 제목 104px(자연 줄바꿈) → 리드 → 대시보드 주소(36px, 한 줄) |

**순위 배너 서열(44자)의 크기:** 34px·700에서 한 줄 폭이 약 820px로 추정된다 [가정]. 배너 안쪽 폭(약 890px)에 들어가지만, CI 글꼴에서 넘치면 둘째 줄로 내려간다. 줄 수 검사가 2줄 초과를 막는다.

## 인터페이스

```python
# publish/render_cards.py
REPORT = "가격 변동 리포트"                      # 우측 상단 라벨(스크립트 1절)
INTRO = "소개"
MIN_GAP = 24                                     # 본문 블록과 상단 바·하단 알약 사이 최소 여백(px)
ORPHAN_EM = 1.6                                  # 마지막 줄 폭이 글자 크기의 이 배수 미만이면 한 음절 줄로 본다

render_html(cards: list[dict], eyebrow: str, *, only: int | None = None, measure: bool = False) -> str
    # only=n이면 n번째 장만 그린다(PNG 한 장씩 굽기용). 마지막 장 여부(`끝`)는 전체 목록 기준이다
    # measure=True면 레이아웃 측정 스크립트를 넣는다. 공개용 cards.html에는 넣지 않는다

visible_text(html: str) -> str                   # <style>·<script>·쪽 표시를 뺀 보이는 글자
check_layout(report: list[dict], cards: list[dict]) -> None   # 겹침·넘침·줄 수·한 음절 줄 → ValueError
bake(cards: list[dict], out_dir: Path, eyebrow: str, events: dict) -> list[Path]
    # 순서: 숫자 검사 → 레이아웃 측정·검사 → cards.html → PNG 장마다 → cards.pdf → 크기·쪽수 검사
    # 산출물: cards.html, 01-cover.png, 02-price.png, …, NN-closing.png, cards.pdf
```

**PNG 파일 이름:** `{순번:02d}-{이름}.png`. 이름은 `cover`, `price`, `chart`, `cost`, `rank`, `closing`이다.

**측정 방식:** 측정 모드 HTML을 브라우저로 열면 스크립트가 장마다 요소 위치와 줄 수를 재어 JSON(ASCII 전용)으로 남긴다. 이 값을 파이썬이 받는 방법은 Step 1에서 실측으로 정한다.

| 후보 | 방식 | 우려 |
|---|---|---|
| A | `--dump-dom`으로 출력한 DOM에서 JSON을 읽는다 | Edge는 분리된 하위 프로세스가 출력을 쓰므로 표준 출력을 받지 못할 수 있다 [미확인] |
| B | 스크립트가 JSON을 `document.title`에 쓰고, `--print-to-pdf`로 만든 PDF의 제목(`/Title`)에서 읽는다 | 파일로 받으므로 Edge에서도 기존 대기 로직이 통한다. PDF 제목 인코딩을 확인해야 한다 [미확인] |

둘 다 실패하면 **멈추고 보고한다.** 대안(PNG 픽셀 판독)은 그때 다시 여쭙는다.
