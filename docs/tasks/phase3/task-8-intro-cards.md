## 착수 전 확인 사항

### 1. 4장 `현재 결과` 문안이 데이터와 맞지 않는 경우가 있다

확정 문안(2026-09-12)은 다음 세 줄이다.

```
T1 {판정} · 시나리오가 달라도 월 사용료 1위는 동일합니다.
T2 {판정} · 서울 프리미엄 격차 {격차}%p.
시나리오별 월 사용료 1위는 {플랫폼}입니다.
```

코드와 대조하니 세 가지가 맞지 않는다.

| # | 문제 | 근거 |
|---|---|---|
| a | **T1은 리전마다 판정한다.** `{판정}` 자리가 하나라 두 리전의 판정이 다를 때 쓸 수 없다 | `model/tco.py t1_verdict(region)`. 대시보드도 T1을 미국 리전·서울 리전으로 나눠 표시한다(2026-09-11 결정) |
| b | T1 줄의 설명 `1위는 동일합니다`는 **기각일 때만 참**이다. 채택이면 틀린 문장이 된다 | T1 가설은 "월 사용료 1위는 워크로드마다 다르다"이다 |
| c | `시나리오별 월 사용료 1위는 {플랫폼}입니다`는 1위가 **모든 시나리오·두 리전에서 하나일 때만** 쓸 수 있다 | 리전마다 1위가 다를 수 있다 |
| d | T2 줄이 명사구로 끝나 무엇을 채택했는지 밝히지 않는다 | 규칙 17: "무엇을 채택했는지 한 줄로 밝힌다" |

현재 승인 스냅샷(2026-09-11) 값 [확인]: T1 미국 리전 기각(전 시나리오 Redshift), T1 서울 리전 기각(전 시나리오 Redshift), T2 채택(39.5%p).

**보완안 (Step 0에서 `/humanize-korean` 점검 후 승인받는다)**

| 위치 | 보완안 | 비고 |
|---|---|---|
| 리드(신규) | `월 사용료가 가장 낮은 플랫폼이 1위입니다.` | `1위`의 뜻을 밝힌다. 다른 목록 장처럼 리드를 둔다 |
| T1 항목 (리전마다 1개) | 굵은 줄 `T1 {판정} · {리전}` | 미국 리전 → 서울 리전 순서 |
| T1 설명 [기각] | `시나리오가 달라도 1위는 {플랫폼}로 같습니다.` | 기존 1줄과 3줄을 합친다. 네 플랫폼 이름이 모두 모음으로 끝나 조사는 `로`로 고정된다 |
| T1 설명 [채택] | `시나리오에 따라 1위가 달라집니다.` | 시나리오별 1위는 대시보드에 있다 |
| T2 항목 | 굵은 줄 `T2 {판정}` | |
| T2 설명 [채택] | `서울 프리미엄은 서비스마다 최대 {격차}%p 다릅니다.` | `{격차}` = 서비스별 서울 프리미엄의 최대-최소 차이 |
| T2 설명 [기각] | `서울 프리미엄의 서비스 간 차이가 {격차}%p로 작습니다.` | |
| 각주 | 기존 두 줄 그대로 | `{작성일} 승인 스냅샷 기준입니다.` / `약정 할인을 제외한 모델 추정치입니다.` |

항목은 3개로 기존과 같다. 가장 긴 설명은 31자(`Databricks`가 1위인 T1 기각, 격차가 세 자리인 T2)로 항목 상한 32자 안이다 [확인].

### 2. 표지 제목이 로컬 글꼴에서 넘친다 (결정 D22)

시험 굽기로 확정 문안 `데이터 플랫폼 네 곳의` / `월 사용료 추적`을 측정했다 [확인 2026-09-15, 작업 폴더에서 측정, 저장소 변경 없음].

| 글꼴 | 표지 제목 | 판정 |
|---|---|---|
| 맑은 고딕(현재 로컬에서 쓰이는 글꼴) | **3줄** (상한 2줄). `곳의`가 둘째 줄로 떨어진다 | 레이아웃 검사 실패 |
| Noto Sans KR(이 PC에 설치됨) | 2줄. 첫 줄 오른쪽 끝 970/1032px | 통과 |

정기 카드는 CI에서 **Noto Sans CJK KR**로 굽는다. 로컬은 글꼴 목록에서 `Malgun Gothic`이 먼저 걸려 맑은 고딕으로 굽는다. 3-1에서 확인한 "로컬과 CI의 줄바꿈이 다르다"의 원인이 이것이다.

**D22 (권고):** 카드 글꼴 목록에 `"Noto Sans KR"`을 `"Malgun Gothic"` 앞에 넣는다.
- 로컬에서도 CI와 같은 Noto 계열 글자 모양으로 굽는다. 소개 카드(로컬)와 정기 카드(CI)의 글꼴이 같아진다.
- CI 출력은 바뀌지 않는다(CI에는 `Noto Sans KR` 이름의 글꼴이 없다).
- Noto Sans KR이 없는 PC에서는 맑은 고딕으로 돌아가고, 넘치면 레이아웃 검사가 굽기를 멈춘다. 잘못된 카드가 조용히 만들어지지 않는다.
- 대안: 표지 제목을 줄인다(예: `플랫폼 네 곳의` / `월 사용료 추적`). 문안 재승인이 필요하고, 로컬·CI 글꼴 차이는 남는다.

### 3. 굽는 곳 (결정 D21)

**D21 (권고):** 소개 카드는 **로컬에서 굽고**, 사용자가 대화에서 실물을 승인한 뒤 커밋·push한다. 게시 워크플로가 `site/cards/intro/`로 복사한다.
- 소개 카드는 한 번 만드는 게시물이다. 숫자는 이미 승인된 스냅샷에서 온다.
- 대화에서 실물을 승인하는 것이 체크포인트다(규칙 14). push도 따로 승인받는다(규칙 4).
- 대안: CI 워크플로가 굽고 검토 PR로 확인한다. 새 워크플로와 PR 문안(규칙 16)이 필요하고, 문구 반려 루프(`revise.yml`)가 날짜 없는 PR을 다루도록 고쳐야 한다. 한 번 쓰는 카드에 비해 크다.

**`chips` 장 (디자인 제안, 실물 승인 대상)**
- 제목 → 리드 → 흰 타일 2×2(차트 장의 흰 패널과 같은 바탕·모서리) → 각주 1줄
- 타일 안: 플랫폼 이름(굵게, 항목 첫 줄 크기) + 과금 단위(보통, 회색)

**`flow` 장 (디자인 제안, 실물 승인 대상)**
- 제목 → 세로 4단계 → 각주 2줄. 리드는 없다(확정 문안에 없다)
- 단계마다 번호 원 + 단계 이름. 단계 사이에 가는 연결선
- 번호는 CSS 카운터로 그린다. 글자가 아니라 숫자 검사 대상이 아니다
- 멈춤 지점(`검토 요청에서 정지`)은 번호 원을 채워 구분한다. 그라데이션은 제목 강조 한 곳만 쓴다(디자인 계획 2절)
